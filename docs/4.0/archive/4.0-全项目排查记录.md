# 鲸鲸 4.0：代码与用户流程排查记录

> main 合入说明（2026-10-31）：本文记录最初基于 c67ea79 的隔离工作区排查。准备上传时发现 main 已推进到 3d71ae6，包含记忆 v2、界面重设计和连发合并修复。因此实际上传已改为在最新 main 上移植。**记忆 v2 的 Store/ChatStore、原有崩溃恢复及 token 预算逻辑保留；已移除的记忆页面和 HTTP 正文入口没有恢复。** 本文旧存储的 journalId 修复和性能对比仅是历史记录，不适用于 main 的记忆 v2，也没有用旧实现覆盖它。最终状态与验证以《4.0-main合入说明.md》为准。

日期：2026-10-31。对象：本工作区的 4.0 源码，以及由它重新编译的启动器。

本轮按“首次安装 → 启动内核 → 连接微信 → 收消息 → 生成回复 → 发文字/表情包 → 改设置 → 故障恢复 → 停止/备份/更新”的顺序检查。E 盘 3.9 安装目录没有被修改。

## 检查边界

- 对 76 个项目自有 JavaScript 文件做语法与相对模块依赖解析检查，对 24 个 Python 文件做 AST 语法检查，对 12 个 PowerShell 脚本做语法解析。C# 与 XAML 通过启动器编译验证。
- 人工重点追踪了桥接启动与恢复、账号绑定、消息调度与时效、文字发送失败、表情包领取/核验/发送/回执、原生设置页、记忆存储与恢复、HTTP 鉴权、命令行工具和发布运维脚本。

- 第三方运行库只核对了相关兼容修复代码；没有逐行审计所有 Python 依赖或原生 DLL。
- 没有向真实微信联系人发送任何消息，没有操作用户的真实聊天记忆，没有执行真实恢复出厂或强制终止操作。微信 4.2 不同小版本、不同账号/权限/窗口环境仍需实机回归。

## 本轮确认并处理的问题

### 桥接首次启动、掉线与恢复

1. 启动器直接运行 Python，绕开旧 bat 守护：账号切换、连接参数变化或看门狗退出后，桥接可能永久停止。启动器增加退出码判断、延迟恢复和连续失败上限；0/1/2 不反复拉起；手动停止会取消恢复任务。
2. 健康检查只要收到非 500 响应就认为就绪，可能把 404 或其他本地程序误认成内核。内核提供服务标识与 PID，启动器核验自身 PID，桥接核验服务标识。
3. 内核尚未就绪时桥接仍继续监听。等待失败后现在退出并显示可诊断状态。
4. 启动器启动服务时可能自动打开已下线网页。现在显式传入 --no-browser。
5. token、数据库目录或连接地址改变后仍沿用旧连接。现在检测这些连接参数并请求桥接重启。
6. UIA 兼容模块在按文件路径加载的兜底路径仍指向迁移前位置。已改为实际 examples 目录。没有改动已验证的 DLL 偏移或放宽账号/窗口核验。
7. 原生启动器缺少单实例保护。增加按安装目录区分的单实例锁。
8. 首次使用需要额外 .NET 环境。此次输出改为包含 .NET 的独立启动器；Node/Python 仍由原有 runtime 提供。
9. 多平台状态显示固定取第一个网关。现在明确读取微信网关；本地免 Key 模型不再显示“还没填 Key”。

### 收消息、识图与文字发送

10. 图片/语音识别耗时和队列等待时间被算成消息过期，可能处理完却不回复。现在在接收时记录时间，识别前剔除真正的历史消息；队列等待不再让已及时收到的消息失效。
11. 自己发出的图片在判断发送者前就进入识别。现在先判断发送者与时效。
12. 长 PNG 截图切片后实际是 JPEG，仍可能标注成 PNG。现在同步修正 MIME。
13. 图片请求可能超过通用 2MB 请求上限而被拦截。视觉端点采用独立上限，超限保留 413 错误。
14. webhook 403/错误响应可能被记成“已连接”。现在检查 HTTP 状态、响应结构及网关启用状态，明确显示 token 或配置问题。
15. 非数组 bubbles 可能被逐字符发送。现在规范为完整文本列表。
16. 某条文字发送失败后仍继续发送后续气泡和表情包。现在终止本次后续发送，保留失败提示。
17. 默认语音接口可能拿到其他服务商的聊天/视觉 Key。现在只选语音专用凭据、目标服务商对应 Key，或相同来源地址的凭据；启动器增加语音 Key/接口/模型设置。

### 表情包使用体验与发送链路

18. 重复点击同一会话测试发送会堆出多个任务。现在复用该会话进行中的任务，任务结束后仍可立即再发。
19. 原生图库没有使用后端提供的相对文件 ID，同名图片可能预览/删除失败。现在保留完整 ID。
20. 页面首次加载后不再刷新，任务结果停在排队中。现在持续刷新状态，并在图库未变化时避免重建全部缩略图。
21. confirmed/unconfirmed/cancelled 没有正确中文映射。现在区分确认、未确认和取消，并给常见窗口/账号/草稿错误提供中文提示。
22. 上传部分超限图片后仍按最初选择的数量显示成功；拖入超过 5 张会静默截断。现在显示实际上传/跳过数量，并明确提示分批；读取文件失败不再引起未处理的界面异常。
23. Node 图库允许的文件可能超过 Python 运输层单独设置的 4MB 上限。Python 的内存保护上限已与图库的 64MB 对齐。原生界面仍保留每批 5 张、单张 4MB 的上传约束；从磁盘加入的较大图片还必须通过解码、像素和发送安全检查。
24. 每次发送安全核验都取完整图库状态，图库大时重复扫描。增加需要 token 的轻量 gate 接口，不扫描图片；安全核验仍在。
25. 图片在预览中被删除时，读取流错误可能未处理。现在处理流错误，避免拖垮服务。

### 记忆与数据保护

26. 快照成功、旧日志清理失败后，重启会重放旧会话。保持快照+增量日志、version=1，新增可选 journalId 关联标识，旧文件仍可读取。恢复备份也生成新标识，旧日志无法覆盖恢复内容。
27. 正常关闭服务重复调用两次记忆 close，导致重复压全量快照。现在只执行一次，并清理配置监听和定时备份任务。
28. 特殊用户 ID 可能取到继承属性而污染共享对象。现在只读取自有档案属性，并安全创建对应记录；JSON 文件结构不变。
29. 记忆写盘失败时，手动备份接口仍可能报成功。现在返回失败，不向停止流程提供虚假的保存成功。
30. 命令行备份工具仍 require 已迁移的 src/memoryBackup，4.0 中直接失败。修正依赖；在线恢复会拒绝直接覆盖磁盘，并提示使用启动器或停止后恢复，避免内存覆盖恢复结果。

### 接口、设置与运维

31. 未授权网页聊天先返回 404，却没有真正停止处理。现在立即返回，回归测试确认不调用模型/记忆处理。
32. JSON null/数组/字符串等输入可能造成处理器异常；中断上传可能留下未完成的读取。现在拒绝非对象输入，处理上传中断；非法 URL 编码返回 400。
33. 账号扫描进程失败后，可能拿旧缓存冒充刷新成功。现在检查退出码。
34. “测试连通”测的是旧设置；清空称呼无法保存；密钥保存失败却清空输入框并显示成功。现在测试当前表单、统一保存称呼，失败时保留密钥输入并显示错误。
35. 界面定时刷新可能重叠。增加刷新互斥；状态接口使用已生效的模型凭据，不再重复读设置文件。
36. 停止脚本按名称或端口可能误停其他程序。收紧为当前目录的进程，停止前请求保存与备份；保存失败时取消停止。强制终止仍不等于完整正常退出。
37. 部署 -Restart 会结束所有 node/python 进程。现在通过按目标目录限制的停止流程处理；部署不再复制本地工具、缓存和备份。
38. 恢复出厂忽略停止失败及备份失败，随后仍可能删除数据。现在遇到这些失败就取消重置，并检查删除目标范围。
39. 更新前语法检查未遍历重构后的子目录。现在递归检查。
40. 安装器可能取到正在运行的旧根目录 exe。明确使用发布目录中的新启动器；更新包同样使用该成品。默认新安装目录采用英文名称，减少路径兼容问题。
