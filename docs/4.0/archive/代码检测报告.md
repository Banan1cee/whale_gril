## 三、高危问题（9 项）

### [H1] bridge · 启动即崩：main() 尾部引用三个未定义名字（已复核，3 路独立确认）

- 位置：`bridge/engine.py:3822`（`contacts_sync_once`）、`3823`（`start_reminder_watch`）、
  `406` / `3850`（`DIGEST_WORKER`）；`REMINDER_RUNNER` 仅在 78 行定义为 None
- 证据：全仓库正则扫描确认三个名字**只有引用、没有定义**，无 import、无动态注入
  （`reminder_watch.py` / `contacts_sync.py` 是从未被接线的死模块）。3822-3823 无 try 包裹。
- 影响：`main()` 启动尾部求值 `contacts_sync_once` 立即 NameError → 进程死在"已启动"日志之前，
  3815-3821 刚起的 7 条守护线程陪葬；即使补上 3822-3823，`reload_config()` 每次走到 406 也必抛
  （且此时配置**已半更新**），`config_watch` 线程静默死亡、热更新永久失效；退出清理 3850 再崩，
  `pipeline.close()` / `listener.stop()` 不执行。
- 建议：补齐三块接线（`contacts_sync_once` 封装联系人推送、`start_reminder_watch` 封装 ReminderRunner
  并赋值 `REMINDER_RUNNER`、digest worker 接线），或先用 try/except + 日志守护这些调用让主循环能活。
- 复核备注：若你最近实机跑过桥接且正常，请确认跑的是不是旧副本——按当前 HEAD 源码静态结论确凿。

### [H2] bridge · OCR 兜底僵尸线程绕过 send_lock，可能重复发送（已复核）

- 位置：`bridge/engine.py:2888-2905`
- 证据：`_th.join(8)` 超时后仅 log"放弃这条"并 `resp = False`，僵尸线程未被取消，仍在
  `with_window_on_top(gui.send_msg(...))` 里跑
- 影响：僵尸稍后成功 → 消息照发但 send_text 已报失败（fail_streak++，两次后 dead_chats 永久停会话），
  下一轮再发就**重复回复真人**；僵尸的 finally 会在任意时刻把 `SEND_STATE["active"]` 清成 False，
  让 40 秒看门狗对真正卡住的发送失明；每条走 OCR 的消息可留一个卡在截屏里的 daemon 线程，无上限累积。
- 建议：加取消标记（线程落键前自查），或把 OCR 兜底移入带 send_lock 的串行执行器；
  僵尸线程不得写 SEND_STATE。

### [H3] bridge · watchdog 40 秒一刀切，长文本慢发送被 os._exit(7) 腰斩

- 位置：`bridge/engine.py:3661-3666`（看门狗）+ `bridge/bg_sender.py:411-413`（逐字投递）
- 证据：`SEND_STATE["active"]` 超 40 秒 → `os._exit(7)`；而 bg 通道逐字节 sleep(charGap)，
  charGap 可配 80ms——1500 字节 GBK 文本单打字就 120 秒，远超 40 秒
- 影响：合法慢发送被当"卡死"杀进程：消息半截留在输入框（下条消息撞 input_not_empty 或叠加乱码），
  重启后 staleAfter 不补发 → **回复永久丢失**
- 建议：超时改"进度心跳"（每次 PostMessage/UIA 操作刷新 start），或按 `len(text)×charGap+固定开销` 动态给预算

### [H4] bridge · restore_win_state 缺 import win32api，前台还原主路径是死代码（已复核，2 路独立确认）

- 位置：`bridge/engine.py:2062-2067`（函数内 import 见 2046-2048，无 win32api）
- 证据：`win32api.keybd_event` 每次必抛 NameError，被 `except Exception: pass` 吞掉，
  同 try 块的 `SetForegroundWindow`（2065）永远执行不到；win32api 的 import 都在更深的嵌套函数里
  （1814/1925/2002/2332），作用域不可见
- 影响：「发完把前台还给用户」的 ALT 解锁 + SetForegroundWindow 主路径一次都没跑过，只剩
  SwitchToThisWindow 兜底——BUGS.md 第 15 行记录过同一函数缺 `ctypes` 的同型事故（3.4.11 修复），属复发
- 建议：import 块补 `import win32api`；`except: pass` 至少换成 debug 级日志

### [H5] bridge · 心跳线程不看 SEND_STATE 就碰 UIA 引擎、抢焦点

- 位置：`bridge/engine.py:3721-3765`（心跳）vs `2233-2288`（uia_send）
- 证据：心跳每 20 秒做 `gui._get_uia()`（可能重写 gate 字节）、`ensure_uia_ready(force=True)`、
  `WeChatGUI()` 构造（注释自认"构造它本身就会抢一次焦点"），全程不检查 `SEND_STATE["active"]`；
  uia_send 的 open_chat/send_text/press_enter（全局真实按键）不全在 gui_lock 内
- 影响：发送打字进行中被心跳抢前台 → Enter/粘贴落到别的窗口；或两线程并发驱动同一 UIA 引擎
  （COM 跨线程 + gate 字节被中途重写），发错窗口甚至 0xC0000005
- 建议：心跳动窗口前先看 `SEND_STATE["active"]`；UIA 引擎统一只在 gui_lock 内调用

### [H6] bridge · uia_boot.ensure 成功路径返回过期 hwnd/pid

- 位置：`bridge/uia_boot.py:504、511-514`
- 证据：`hwnd, pid = win["hwnd"], win["pid"]` 在 504 行取值后，`restore_wechat()` 内部
  `win.update(w2)` 换了新窗口，但返回时用的还是旧局部变量（对比 559-564 延迟分支用 `w2["hwnd"]` 是对的）
- 影响：engine 把过期 hwnd 写进 `ACCOUNT["hwnd"]`，`_bg_hwnd()` 拿它 PostMessage——
  本模块文档排第一的「窗口句柄过期」问题从成功路径被带回：零焦点通道全失败，句柄被系统回收复用后
  消息可能投到别的窗口
- 建议：restore 成功后从更新后的 `win` 取值再返回

### [H7] pipeline · 管理员魔咒是死代码，非主人永远用不了管理员命令（已复核）

- 位置：`src/pipeline/chat.js:838-848`（配合 826、1080-1084）
- 证据：`838: if (!isMaster && !allowAll) return null;` 一票否决后，839 行
  `if (!isMaster && !allowAll && !(adminUntil > now))` 永远不可达
- 影响：非主人发魔咒拿到「管理员权限 N 分钟。可以发：状态 / 改模型 / …」的承诺（832），
  实际一条都执行不了；「退出管理」（1081）对主人也是空操作——主人本来就绕过 838，权限无时限
- 建议：838 改为 `if (!isMaster && !allowAll && !(Number(state.adminUntil) > nowMs)) return null;`，
  删掉 839-848 的冗余判断；若要真时限，主人路径也检查 adminUntil

### [H8] pipeline · 消息前缀剥离正则吞 URL 协议头（已复核）

- 位置：`src/pipeline/chat.js:224`
- 证据：`replace(/^[A-Za-z0-9_\-]{4,}:\s*/, '')` 中 `\s*` 允许零空白：
  `"https://example.com"` 被剥成 `"//example.com"`；`Note: xxx`、`PS: xxx` 同样中招
- 影响：裸链接开头的消息正文被截断——链接解读失效、残缺文本进提示词/搜索/记忆，模型基于错文本作答
- 建议：`\s*` 改 `\s+`（wxid 前缀本来就有换行/空格），一行修复

### [H9] launcher · DiagPage 每 2 秒在 UI 线程递归枚举整个安装目录（已复核）

- 位置：`launcher/Views/DiagPage.xaml.cs:163、179-195`；触发链 `MainWindow.xaml.cs:55-57、239`
- 证据：`SizeOf()` 内 `Directory.EnumerateFiles(path, "*", AllDirectories).Sum(...)`，
  对 BaseDir（含 runtime/node、python site-packages，数万级文件）+ DataDir + backups 同步全盘求大小，
  MainWindow 2 秒 DispatcherTimer 无节流驱动 + DiagPage 自带 1.5 秒定时器双通道
- 影响：诊断页开着时每 2 秒冻结一次 UI，「一打开诊断页就卡死」
- 建议：SizeOf 移 `Task.Run` 并缓存（30-60 秒算一次）；RefreshAsync 加节流
