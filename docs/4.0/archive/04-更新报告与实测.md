## 4. 实测

### 4.1 环境与方法

- Windows 11、Node 24.18.1、Python 3.13.14、.NET SDK 10.0.403；无模型 Key（演示模式）；微信已登录（桥接可读库）。
- 启动器 UI：提权启动 `WhaleLauncher.exe`，用 UI Automation 抓窗口与 7 页文本，再点顶栏启动/停止并关窗。
- 本地 API：在临时 data 目录 + 随机端口起独立实例，逐项请求；不触碰真实微信。
- 约束：未向任何真实会话发送消息。

### 4.2 启动器 UI（实测通过）

### 4.3 桥接启动（实测通过，修复后）

- 修复前：启动即 `TypeError: main.<locals>.start_reminder_watch() got an unexpected keyword argument 'http'`，code=1 退出，启动器不拉起（`data/bridge.log` 有实例）。
- 修复后：日志依次出现「提醒调度已启动」「已启动」「联系人同步：成功（4450 条）」「发送通道预热完成（UIA 可用）」「账号窗口已确认」。
- 未测：真实消息收发、提醒准点到点实发、表情包真实发送（本轮按约定不向真实会话发消息）。

### 4.4 本地 API（28 用例，26 通过）

## 6. 未覆盖与限制

- 真实微信收发、提醒到点实发、表情包真实发送：按约定未发消息；桥接已能连上并预热 UIA，具备后续真机验收条件。
- 托盘：代码未实现，验收不要找托盘图标。
- 安装包体积、提醒 11ms 准点：未复测（需要出包与到点等待）。
- Node 的 10 条 `spawn EPERM`、Python 的 5 条 ACL：沙箱限制，非代码失败；CI 上同套测试可跑。

## 7. 发布建议

1. B1 已修，必须带上；否则 4.0 桥接不可用。
2. B5 建议随 4.0 补掉（状态页空列表观感差），B2/B3 可排到 4.0.1。
3. B4 需在普通 Windows（非沙箱）用目标 Node 复跑两条用例；若是真实兼容问题，改 reparse point 检测后再发。
4. 发布前在干净机跑一遍：安装 → 启动器 → 填 Key → 微信收一条 → 提醒一条 → 表情包一张。
