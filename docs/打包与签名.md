# 打包与签名（安装包都在 GitHub Actions 上打）

本机**不再出安装包**。安装包由 `.github/workflows/installer.yml` 在 GitHub 的
`windows-latest` 上构建：Python 与 Node 打进包里，.NET 10 桌面运行时随包、目标机缺失时
安装器请求管理员授权后静默安装。这样做换到三件事：

1. **能签名**：证书只放在仓库 secrets 里，构建机签完就删，私钥不落地到本机。
2. **出包可追溯**：谁、哪次提交、哪个版本出的包，在 Actions 运行记录里都有。
3. **本机干净**：不用为了出包装 Inno Setup / Python / Node，也不用把 200MB 产物存本地。

---

## 一、流水线做了什么

`installer.yml` 一个 job 跑完，全部在 Windows runner 上：

| 步骤 | 做什么 | 产物 / 检查点 |
| --- | --- | --- |
| 环境 | setup-node 24、setup-python 3.12、setup-dotnet 10.0.x | 版本打印进日志 |
| 解析版本号 | tag 去 `v` → `workflow_dispatch` 手填 → `package.json` | 归一成 `x.y.z`，写进 `GITHUB_ENV` |
| 构建运行环境 | `scripts/build-runtime.ps1`：取 node.exe、解 CPython 3.12 embeddable、离线装桥接依赖 | `runtime\node.exe`、`runtime\python\`、`runtime\manifest.json` |
| .NET 运行时 | `scripts/fetch-dotnet-runtime.ps1`：从 aka.ms 下载，**校验 Authenticode 签名确实是微软** | `runtime\dotnet\windowsdesktop-runtime-10-win-x64.exe` |
| 启动器 | `dotnet publish`（framework-dependent 单文件） | `launcher\publish\WhaleLauncher.exe` → 覆盖根目录那份 |
| 签启动器 | `scripts/sign-windows.ps1` | **必须在编译安装包之前**，否则包里嵌的是未签名 exe |
| 安装器 | 用仓库自带的 Inno Setup 7.1.1（`tools/innosetup/`，缺了才联网下），`ISCC --define=AppVersion=<版本> installer\whale.iss` | `artifacts\setup\whale-girl-<版本>-setup.exe` |
| 签安装包 | 同一个签名脚本，签 setup.exe | 摘要里写「已签名 / 未签名」 |
| 安装烟测 | 静默装到临时目录 → 逐个核对文件 → 跑一次 `import` → 静默卸载 | 见下方「烟测查什么」 |
| 上传 | Artifact `whale-girl-setup-<版本>`，含安装包与 `SHA256SUMS.txt` | 保留 30 天 |
| Release | 只有 tag 触发才建 | `gh release create`，挂了才 `--clobber` 补传 |

「构建运行环境」这步要装约 380MB 的 Python 依赖，首次约 6–10 分钟，所以加了
`actions/cache`（缓存 `runtime\python` 和 `node.exe`）。改了 `build-runtime.ps1` 里钉的
依赖版本、但 CI 好像还装着老版本时，把 `installer.yml` 顶部的 `RUNTIME_CACHE_VERSION`
加一，强制重建。

Inno Setup 7.1.1 的官方安装包也带在 `tools/innosetup/`（14.3MB，官方 license 允许二进制
再分发）：CI 直接用仓库里这份，版本钉死、不依赖网络，仓库里没有时才回退下载。升级步骤见
`tools/innosetup/README.md`。它只是构建工具，不会进用户的安装包。

### 烟测查什么

只量 exe 大小证明不了「包里真的有 Python」。烟测会把安装包真装一遍，然后核对：

- `WhaleLauncher.exe`、`server.js`、`src\core\master.js`、`bridge\engine.py` 都在
- `runtime\node.exe`、`runtime\python\python.exe`、`runtime\manifest.json` 都在
- `runtime\dotnet\windowsdesktop-runtime-10-win-x64.exe` 在
- **`runtime\wheelhouse` 不在**（构建缓存，混进来白多 117MB）
- 包内 `node.exe -v` 能跑
- 包内 `python.exe` 能 `import wechatauto, psutil, win32com, uiautomation`

任一条不过，这次运行就红，不会产出「看着有包、装完用不了」的安装包。

## 二、怎么触发

**手动（日常出包）**

1. 仓库 → Actions → 左侧 `installer` → `Run workflow`
2. 版本号留空就用 `package.json` 的版本；要覆盖就填 `4.0.0` 这种
3. 跑完在本次运行页面底部 Artifacts 下载 `whale-girl-setup-<版本>.zip`

**打 tag（发版）**

```powershell
git tag v4.0.0
git push origin v4.0.0
```

tag 触发时版本号取自 tag（`v4.0.0` → `4.0.0`），并且会自动建 GitHub Release、把安装包和
`SHA256SUMS.txt` 挂上去。仓库已经存在同名 Release 时不会覆盖，会退回 `--clobber` 补传资产。

> 推送与发版前先自查：`git status`、`git log`、要推的分支与 tag。规则见 `~/.dsh/AGENTS.md`。

---

## 三、版本号

- 版本号只认一处：`package.json` 的 `version`（tag / 手填优先于它）。
- `x.y` 会自动补成 `x.y.0`（`4.0` → `4.0.0`），因为 Inno 的版本资源要三段式。
- 产物名固定 `whale-girl-<版本>-setup.exe`，安装包属性里的文件版本 = 这个版本。

## 四、签名（当前状态：还没有证书）

**现状：仓库没有配置代码签名证书，CI 会跳过签名，摘要里写明「未签名」。**
没有签名的安装包，用户双击时 Windows SmartScreen 会提示「Windows 已保护你的电脑」，
需要点「更多信息 → 仍要运行」。功能不受影响，只是观感不好。

### 拿到证书之后：加两个 secrets 就能签

代码已经写好了（`scripts/sign-windows.ps1`），**不需要改任何代码**，只加 secrets：

1. 由**仓库属主账号**（`Banan1cee`）打开
   `https://github.com/Banan1cee/whale_gril/settings/secrets/actions`
   （协作者账号没有加 secrets 的权限）
2. 新增 `WINDOWS_SIGNING_PFX_BASE64`：把 PFX 转成 base64 后粘贴
   ```powershell
   [Convert]::ToBase64String([IO.File]::ReadAllBytes('D:\cert\whale-codesign.pfx'))
   ```
3. 新增 `WINDOWS_SIGNING_PFX_PASSWORD`：PFX 的密码
4. 重新跑一次 `installer`；摘要里会变成「已签名（CN=…）」

签名顺序在流水线里已经排好：启动器先签 → 再编译安装包 → 再签安装包。
证书文件只在构建机上临时落盘，签完在 `finally` 里删掉。

### 证书怎么选

| 方式 | 能不能直接进 CI | 说明 |
| --- | --- | --- |
| OV 代码签名证书（PFX） | ✅ 就是上面这套 | 最省事；SmartScreen 需要攒一段信誉才完全放行 |
| EV 代码签名证书 | ⚠️ 多数是硬件 token | 没有 PFX 就没法进 CI，要用厂商的云签名（如 SSL.com eSigner） |
| Azure 可信签名（Trusted Signing） | ✅ 但要另写步骤 | 微软云签名，需要 Azure 订阅 + 身份审核；要替换成 `azure/trusted-signing-action` |
| SignPath.io | ✅ 走它家的 GitHub App | 公共仓库可申请免费签名，签名在它服务器上完成 |
| 自签名证书 | ✅ 技术上能签 | 只适合内部测试；SmartScreen 仍会拦，别当正式方案 |

> 提醒：签名≠立刻不弹 SmartScreen。新证书有信誉积累期，OV 证书通常要装机量上来才安静；
> EV 证书和 Azure 可信签名没有这个积累期。这是微软的策略，不是包的问题。

### 想在没有证书时也强制卡签名

跑 `scripts/sign-windows.ps1 -Require`（或改 workflow 里那两步加 `-Require`），
没证书就直接失败，避免误把未签名包发出去。

## 五、产物与怎么验

| 位置 | 内容 |
| --- | --- |
| Actions 运行页面 → Artifacts | `whale-girl-setup-<版本>.zip`（安装包 + SHA256SUMS.txt） |
| tag 触发的 GitHub Release | 安装包 + SHA256SUMS.txt 作为资产 |
| 运行摘要（Summary） | 版本、大小、SHA256、安装包与启动器签名状态、内置 Node/CPython 版本 |

本地验证：

```powershell
Get-FileHash .\whale-girl-4.0.0-setup.exe -Algorithm SHA256   # 对上摘要里的值
Get-AuthenticodeSignature .\whale-girl-4.0.0-setup.exe | Format-List Status, SignerCertificate
```

### 装上之后的行为（给用户交代清楚）

- **安装本身不弹 UAC**：装在 `%LOCALAPPDATA%\Programs\WhaleGirl`，不需要管理员。
- **只有缺 .NET 10 桌面运行时才弹一次 UAC**：安装器检测 `C:\Program Files\dotnet\shared\Microsoft.WindowsDesktop.App\10.*`，
  缺失就用 `ShellExec('runas')` 单独提权跑随包的安装包，装完复检；用户取消 UAC 会明确提示手动安装路径。
- 用户如果是**标准账号**（不是管理员），提权会失败，安装器会给出随包安装包的路径让用户找人代装；
  这种情况本来就装不了 .NET 运行时。
- 卸载时删掉安装目录，保留 `data\`（用户数据），并清掉 `runtime\dotnet` 里的 .NET 运行时安装包。

## 六、常见失败排查

| 现象 | 原因 / 处理 |
| --- | --- |
| `构建运行环境` 步骤红，日志有 `No matching distribution` | 依赖版本在 PyPI 上不存在或被 yank。改 `scripts/build-runtime.ps1` 的 `-Packages` 钉一个存在的版本，再改 `RUNTIME_CACHE_VERSION` |
| 同一个依赖装了老版本 | 缓存命中。改 `RUNTIME_CACHE_VERSION` 加一 |
| `找不到 ISCC.exe` | Inno Setup 下载失败且 chocolatey 兜底也失败。重跑；本机已装 Inno Setup 7 只对本机打包有效，CI 不用它 |
| `编译安装包` 红，日志里是 `Source file ... not found` | `.iss` 里引用的文件没生成（`launcher\publish\WhaleLauncher.exe`、`runtime\dotnet\…`）。看前一步 |
| 安装烟测红：`安装后缺文件` | `.iss` 的 `[Files]` 排除表把它排掉了，或某步没产出。按列出的文件名对 |
| 安装烟测红：`wheelhouse 不该在安装包里` | 排除表被改了 |
| 安装烟测红：包内 Python import 失败 | `build-runtime.ps1` 装依赖没收敛，看它第 4 步的轮次日志 |
| 签名步骤红：`找不到 signtool.exe` | runner 没带 Windows SDK。改成先装 SDK，或去掉签名 secrets 先出未签名包 |
| 签名步骤红：`PFX 解码失败` | `WINDOWS_SIGNING_PFX_BASE64` 不是纯 base64（带换行没事，带 `data:` 前缀不行） |
| Release 步骤红 | 同名 tag 的 Release 已存在，脚本会自动退到 `--clobber`；仍失败就看 `gh` 的报错 |

## 七、和本地打包脚本的关系

- `scripts/build-release.ps1` 还在，但**只用来打旧式的两个 zip**（源码包 / 完整包），不再产安装包。
- 安装包的一切（运行时、启动器、Inno 编译、签名、烟测）都在 CI 里，本机跑不了也不需要跑。
- 本地要验证安装包，从 Artifacts 下载即可；不要用本地 Inno Setup 复刻一遍，
  那样出来的包和 CI 的包不是同一个东西，签名也对不上。
