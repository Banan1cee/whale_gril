# 接入微信群

> 最后更新：2026-10（本机实测）

## 先说结论

- **微信 3.9 旧版客户端已经不能用了**：服务端强制最低版本，登录时直接提示「版本过低」，改不了。WeChatFerry / Wechaty 的免费 puppet 路线**全部失效**。
- 个人微信现在**免费**能走的路：**微信 4.x 自动化**（`wechatauto-replica`）——不注入 DLL、不改微信客户端，读消息靠解密本地数据库，发消息靠驱动窗口。本机已搭好。
- 想更稳/合规：企业微信官方能力（进不了个人群）。
- 想省事：第三方中转服务（通常收费）。

**无论哪条路，个人微信号自动化都不是官方接口，有账号风险。请只用小号 + 测试群。**

## 方案 A：微信 4.x 自动化（推荐，本机已就绪）

### 它怎么工作

| 环节 | 做法 | 说明 |
| --- | --- | --- |
| 读消息 | 解密微信 4.x 本地 SQLite（只读） | 需要微信处于登录状态（密钥在进程内存里） |
| 发消息 | 零焦点通道：窗口消息 + GBK 字节注入 | **不抢前台**；失败才退回 UIA / 键盘 / OCR |
| 注入/杀毒 | 无 | 不往微信进程注入，不需要关杀毒 |
| 消息去重 | 桥接里带 watermark | 重启不重复推送老消息 |

发消息的通道按顺序试，前一条成功就不走后面的：

| # | 通道 | 抢前台 | 要求 |
| --- | --- | --- | --- |
| 0 | **零焦点**（`bridge/bg_sender.py`） | ❌ | 微信未最小化、两边权限一致、中文系统 |
| 1 | UIA（`wechatauto`） | ⚠️ 可能 | 控件树可用 |
| 2 | 键盘（Ctrl+F + 剪贴板） | ✅ 会 | 无 |
| 3 | OCR（截图找按钮） | ✅ 会 | 无 |

零焦点通道的原理和实测数据见 [`docs/微信消息后台发送.md`](微信消息后台发送.md)。
自检：`python -m bridge --bg-probe`（打印前后前台窗口号，直接看有没有被抢）。

### 本机已准备

| 组件 | 状态 |
| --- | --- |
| Python 3.12.10 | 已装 |
| `wechatauto-replica` 1.2.7.0 | 已装（支持微信 4.1.12+，本机 4.1.13.65） |
| 桥接脚本 | `examples/wechatauto_bridge.py` |
| 启动器 | `启动微信桥接.bat` |
| 微信网关 | `config.json` 已开启，token 随机生成 |

### 步骤

1. **微信 4.x 用小号登录**（当前登录窗口已打开）。
   - 不用小号也行，但机器人会用你的身份说话，强烈建议小号。
   - 同一个微信号不能同时登两台 PC；小号用自己手机扫码即可。
2. 双击 `启动鲸鱼娘.bat`（鲸鲸服务），网页里可以先用演示模式。
3. 双击 `启动微信桥接.bat`，看到「开始监听新消息…」就是成功了。
4. 用 小号 在测试群发「@鲸鲸 在吗」。

- 日志：`data/wechat-bridge-4x.log`
- 停止：桥接窗口 `Ctrl+C`；鲸鱼娘窗口 `Ctrl+C`

### 注意

- **微信不能退出登录**：退出后数据库密钥失效，重新登录后桥接会自动重新提取（第一次约几秒）。
- **发送不再抢前台**：默认走零焦点通道，发消息时你可以继续用电脑。只有它失败时才会退回「把微信拉到前台」的旧通道（日志里会写「后台通道没发出去（原因）」）。
- **零焦点通道的两个硬要求**：微信窗口不能最小化（不用在前台）；桥接和微信的权限要一致（都普通或都管理员）。
- 微信 4.x 小版本升级可能影响「发消息」的 UI 自动化；「读消息」基本不受影响。
- 群聊规则仍然生效：默认只有被 @ / 叫名字才回话，有冷却和每分钟上限（见下面「群聊礼仪」）。
- 只建议放进测试群，别群发、别营销。

## 方案 B：第三方中转服务（付费，省事）

思路：

```
微信群 ──> 中转服务(收消息) ──POST──> 鲸鲸 /webhook/wechat
                                    │
微信群 <── 中转服务(发消息) <──POST──┘  outboundUrl
```

1. `config.json` 里开启网关并填地址：

```json
{
  "gateway": {
    "wechat": {
      "enabled": true,
      "inboundToken": "换成你自己的随机字符串",
      "outboundUrl": "https://你的服务商/api/send",
      "outboundHeaders": { "Authorization": "Bearer 服务商给你的token" }
    }
  }
}
```

2. 重启服务，把服务商的「消息回调地址」填成：

```
http://你的地址:8787/webhook/wechat?token=换成你自己的随机字符串
```

3. 字段对不上就让服务商改，或写几十行转换脚本（照抄 `scripts/mock-gateway.js`）。
4. 本地先联调：

```bash
node scripts/mock-gateway.js --demo
```

## 方案 C：企业微信（官方、合规）

两条能力，注意它们**进不了个人微信群**：

1. **群机器人 webhook**：只能往外发（日报、播报、通知），收不到群消息。
2. **智能机器人 / 自建应用**：企业微信 4.x 支持在群里 @ 智能机器人提问（需要企业认证和管理员配置），可接收消息回调，把回调转给本程序 `/webhook/wechat`。这是**官方能力**，没有封号风险，门槛是企业认证。

| --- | --- |

## 群聊里怎么不惹人烦（重要）

默认参数已经很保守，建议先照默认跑几天：

| 参数 | 建议 |
| --- | --- |
| `requireAt` | 保持 `true`，只在她被叫到时说话 |
| `freeChatChance` | 想活跃一点再开到 `0.03 ~ 0.08`，别超过 `0.15` |
| `cooldownSec` | 群越大越要调高（30~60 秒） |
| `maxRepliesPerHour` | 20~30，防止刷屏 |
| 群白名单 | 建议只把机器人放进 1~3 个测试群 |

另外：

- 不要让她回复所有人的每条消息（那叫刷屏机器人）。
- 不要让她在群里 @ 所有人或者发广告。
- 群里有人吵架她会打圆场，但要避免让她站队或输出敏感内容。
- 建议在群里公示一下「这是 AI 鲸鱼娘」，避免误会。

## 常见问题

**Q：机器人收不到群消息？**  
A：① 中转服务只推了私聊/没开群消息；② 消息格式里没带 `chat_type: "group"` 或 `room_id`，被当成私聊处理了；③ token 不对（看控制台 `webhook token 校验失败`）。

**Q：被 @ 了也不回？**  
A：检查消息里有没有「鲸鲸 / 鲸娘 / 小鲸」这些别名，或 `at_me: true`。

**Q：同一条消息回了两遍？**  
A：中转服务重试了。给消息带稳定 `msg_id`，本程序会去重。

**Q：桥接提示「未找到微信数据库目录」/「已加载 0/N 个密钥」？**  
A：微信 4.x 没登录。登录后重跑桥接（密钥在进程内存里，未登录拿不到）。

**Q：发送失败/发错会话？**  
A：桥接运行时别同时操作微信窗口；日志 `data/wechat-bridge-4x.log` 会有具体原因。发送前有回读校验，失败会重试。

**Q：重启后记忆还在吗？**  
A：在。`data/store.json`。想清空就删 `data/`。

**Q：能只让某个群用吗？**  
A：可以。桥接脚本顶部 `ONLY_CHATS = []` 填会话名列表即可（比如 `["深海鱼塘"]`）；中转方案则在中转服务侧过滤。

## 常见问题：一直刷「拒绝访问」error(5, 'SetWindowPos')

现象：桥接日志里反复出现

```
调整微信窗口失败： error(5, 'SetWindowPos', '拒绝访问。')
UIA 发送异常：error(5, 'SetWindowPos', '拒绝访问。')
UIA 不可用，走 OCR 兜底
发送通道预热：UIA 不可用
```

先看**程序放在哪个目录**：微信的 Qt accessibility 只能在**纯 ASCII 路径**下热激活成功。
路径里带中文（例如 C:\Users\张三\Desktop\...、D:\我的程序\...）时，
ensure_window() 会超时 30 多秒返回 False，之后所有发送都退到 OCR 并报这个错。

处理：把整个文件夹移到纯英文路径（D:\whale-girl-3.0）后重启
启动鲸鱼娘.bat + 启动微信桥接.bat。

如果路径已经是纯英文还报错，按顺序试：

1. 关掉桥接黑窗口，跑 一键修复并自检.bat，把最后的「结论」发出来；
2. 重启一次微信（微信长期运行后，进程内模块枚举可能被限制）；
3. 确认微信不是以管理员身份运行、也没有开「兼容模式」。

## 常见问题：日志里「热激活 UIA 失败」

「热激活 UIA」= 桥接在内存里给 Weixin.dll 写一个字节，打开微信的 Qt 无障碍开关。
不开这个开关，UIA 看不到控件，ensure_window() 会失败，之后所有发送都发不出去。

这句日志背后有三种完全不同的原因，先跑诊断：

```
runtime\python\python.exe tools\uia-diag.py --all
runtime\python\python.exe tools\uia-diag.py --probe
```

| 诊断里看到的 | 原因 | 怎么办 |
| --- | --- | --- |
| 主窗进程里「枚举不到 Weixin.dll」 | A：拿到的是微信子进程 / 权限不足 / 微信刚重启 | 关掉微信重新登录，**立刻**启动桥接；确认微信没有以管理员运行；确认是 64 位 Python（包内自带的就是） |
| 「候选 RVA 0 个」 | B：这个微信版本库还不支持 | 升级 wechatauto-replica，或换回 4.1.13.65 / 4.1.15.53 |
| 有候选但热激活失败 | C：补丁写了 mmui 没出现（版本对不上/被保护） | 重启微信后立刻重试；仍失败只能等库更新 |

另外两个**已知会让它必然失败**的环境问题：

1. **程序路径含中文**（比如 C:\Users\张三\Desktop\...）→ ensure_window() 超时 37 秒返回 False，发送一律报 error(5, 'SetWindowPos', '拒绝访问')。放到 D:\whale-girl-3.0 这种纯英文路径即可。
2. **微信窗口缩在托盘**（没有标题为「微信」的可见主窗）→ 找不到 hwnd，也会走到失败分支。先把微信窗口点出来。

桥接现在会在预热失败时自动把上面这三类原因打印到日志里（UIA 诊断（原因A/B/C）：…），不用再猜。

## 常见问题：日志里「未配置 outboundUrl，回复只打印在控制台」

**这句不是错误。** 本地桥接模式下，服务端把回复写在 /webhook/wechat 的 HTTP 响应里交还给桥接，
桥接再用 UIA 发到微信 —— 所以「没有 outboundUrl」本来就是正常的（只有自建中转服务才需要它）。

从 3.0.6 起这条日志会按真实情况分开说：

| 日志 | 含义 | 要不要管 |
| --- | --- | --- |
| 回复已交给本地桥接发送（N 条） | 桥接来取的，回复交给它发了 | 不用管（INFO） |
| 这条回复不会到微信：既没有 gateway.outboundUrl，也不是本地桥接请求 | 请求不是桥接发的，也没有中转地址 → 确实发不出去 | 要么用「启动微信桥接.bat」，要么配 outboundUrl |

判断自己是不是「只开了服务、没开桥接」：任务栏/控制台里应该**有两个窗口**（服务 + 桥接）。
只有服务窗口时，回复只落在控制台，微信里当然收不到。启动横幅现在也会写明：

```
回复发送：   本地桥接（要另开一个「启动微信桥接.bat」窗口，回复才发得出去）
```

## 看状态：桥接在线吗？UIA 通吗？ffmpeg 装了吗？

桥接每 20 秒给服务端发一次心跳（POST /api/bridge/heartbeat，带 UIA 和 ffmpeg 状态）。
网页设置面板里会显示成一行：

| 显示 | 含义 | 怎么办 |
| --- | --- | --- |
| wechat：桥接在线 · UIA 正常 | 一切正常 | 不用管 |
| wechat：桥接在线 · UIA 不可用（消息发不出去…） | 能收消息，但打不进微信窗口 | 看桥接窗口报错，按上面「热激活 UIA 失败」排查 |
| wechat：桥接离线 ← 微信里收不到回复 | 桥接没开/崩了 | 双击 启动微信桥接.bat |

也可以用命令行看：

```
curl -s http://127.0.0.1:8787/api/status
```

返回里 gateways[].bridge 就是：{"online":true,"lastSeenSec":3,"uia":true,"ffmpeg":true}。
45 秒没有心跳即视为离线。

## 兜底通道：UIA 挂了也能发（键盘通道）

UIA 依赖微信的 accessibility gate，微信跑久了或窗口状态怪的时候整条路都会挂。
3.0.13 起多了一条**完全不碰 accessibility** 的兜底：Ctrl+F 搜会话 → 剪贴板粘贴 → 回车发送，
发完**回读数据库**确认这条真的发出去了（搜错会话能立刻发现，按失败处理）。

- 触发条件：UIA 连"强制重新热激活"之后仍然发不出去。
- 代价：会**抢前台**（把微信窗口切到最前），并且比 UIA 慢（约 2~3 秒）。
- 关掉它：config.json → wechat.keyboardFallback: false。
- 抢不到前台的机器（某些远程/锁屏/多桌面场景）会直接放弃并写日志，不会瞎按键。

## 能不能不占着这台电脑？（零焦点发送）

先区分两件事，容易混：

| 开关 | 真实含义 |
| --- | --- |
| `wechat.backgroundSend` | 「尽量别占前台」：先让 UIA 在后台发，失败再拉前台，发完还原。**不代表一次都不抢** |
| `wechat.bgSend` | **结构上不碰前台**：只用窗口消息，代码里没有 `SetForegroundWindow` / `SetWindowPos` / `SetFocus` / `SendInput` |

3.56 起默认先走 `bgSend`（`bridge/bg_sender.py`）：

```
WM_SETFOCUS 伪焦点 → GBK 字节逐个 WM_CHAR → WM_MOUSEMOVE + 点击发送按钮
```

不激活窗口、不移动窗口、不改 Z 序。原理、编码表和实测数据见
[`docs/微信消息后台发送.md`](微信消息后台发送.md)。

它失败时才退回旧链路（UIA → 键盘 → OCR），日志会写清原因：

| reason | 处理建议 |
| --- | --- |
| `minimized` | 窗口缩进任务栏了。不用拿到前台，只要别最小化 |
| `uipi_denied` | 微信和桥接权限不一致。把桥接也设成管理员（或把微信降回普通） |
| `tree_not_ready` | 控件树没物化。4.2 需要 wechatauto 的 gate 热激活，必要时提权 |
| `chat_not_found` | 会话不在列表前十几个。旧通道会自己搜索 |
| `input_not_empty` | 输入框里有草稿。旧通道会先清空 |

想确认到底有没有抢前台：

```bat
python -m bridge --bg-probe
```

打印 `前台 = A → B | 被抢 = False` 就是没抢。

想彻底不抢（失败宁可不发）：`wechat.bgSend.fallbackToForeground = false`。

> 群聊真 @（要用 UIA 选人）和引用回复仍然走旧通道，这两种会抢前台。

### 那还需要虚拟机吗

既然后台就能发，虚拟机**不是必须的**。什么情况下才值得上虚拟机：

| 方案 | 代价 | 适合 |
| --- | --- | --- |
| 直接用（后台发送） | 0 | 绝大多数人；电脑照常用 |
| 虚拟机里跑一套微信 + 鲸鲸 | 内存 8G 起、要单独装微信并重新扫码登录、路径必须在虚拟机内是英文 | 不想动自己电脑、想让它 7×24 挂着 |
| 另一台旧电脑 / 迷你主机 | 一台机器的钱 | 长期挂着、要稳 |
| 云服务器 Windows | 要能装微信并保持登录、扫码登录有风险 | 不推荐，微信容易判异常 |

Win11 **家庭版**没有 Hyper-V / 沙箱，但 VMware Workstation Player、VirtualBox 都能装
（本机固件虚拟化已开启、SLAT 可用、32G 内存、D/E/F 各 260G+ 空闲，装虚拟机条件够）。
真要走虚拟机，规则和实机一样：**安装路径必须纯英文**，否则 UIA 热激活会永久失败。
