# 维护手册（给 creator 自己看）

目标：改完代码**一次命令**就能安全地跑到运行目录，**一次命令**就能出可发布的包。
不要再手工 `Copy-Item` —— 今晚两次事故都是它：一次目录套娃、一次把 `data\` 和配置覆盖掉。

## 目录分工

| 目录 | 角色 | 说明 |
| --- | --- | --- |
| `D:\whale-girl-3.0` | **唯一源码目录** | 所有改动只在这里做；带 `runtime\` 方便跑测试 |
| `F:\whale-girl-3.0-full` | **运行目录** | 微信桥接和服务在这跑；`data\`（Key、聊天记忆）在这里，**任何同步都不许覆盖** |
| `E:\...\whale-girl-2.9.2` | 历史副本 | 只当作旧数据来源（今晚的聊天记忆就是从它恢复的），不再改 |
| `whale-girl-3.0.zip` / `-full.zip` | 发布产物 | 由 `build-release.ps1` 生成，别手工打包 |

## 两个命令

```powershell
# 1) 把源码同步到运行目录（默认不重启；-Restart 会重启服务+桥接）
powershell -File scripts\deploy.ps1 -Target F:\whale-girl-3.0-full
powershell -File scripts\deploy.ps1 -Target F:\whale-girl-3.0-full -Restart

# 2) 出发布包（测试 → 发布自检 → 打两个 zip → 从 zip 里读文件复核）
powershell -File scripts\build-release.ps1
powershell -File scripts\build-release.ps1 -OutDir D:\release -SkipFull
```

`deploy.ps1` 会做 MD5 逐文件校验，**关键文件不一致就报错并且不重启**；`build-release.ps1` 在测试或自检不过时直接中断，不出包。

## 改 bug 的流程

```
复现（日志/接口/真实文件）
  → 定位根因（哪行判断、哪个环境假设）
  → 一处修复（同类判断只保留一份实现）
  → 补回归测试（修复前失败、修复后通过）
  → 写进 BUGS.md 一行
  → deploy.ps1 -Restart  →  现场确认
  → build-release.ps1     →  出包
```

## 版本号规则

- 修 bug、不动配置格式和对外接口 → **补丁号** +0.0.1（3.0.4 → 3.0.5）
- 加字段/加接口但老配置还能用 → **次版本号**（3.0.x → 3.1.0）
- 改 `config.json` 结构、要用户手工迁移 → **主版本号**
- 每次都要在 `CHANGELOG.md` 顶部加条目；`release-check` 会校验「`package.json` 版本 == CHANGELOG 最新条目」

## 已知的坑（都真实踩过，别重踩）

| 坑 | 表现 | 规矩 |
| --- | --- | --- |
| 程序放在**中文路径** | 桥接发送一律 `error(5) 拒绝访问`，`ensure_window()` 超时 37s | 运行目录必须是纯英文路径；桥接启动会自检并告警 |
| 微信图片是 **wxgf（HEVC）** | 视觉接口报「图片输入格式/解析错误」 | 必须能转码：`ensure_ffmpeg_env()` 会找 `C:\ffmpeg\bin`；日志里要有「找到 ffmpeg」 |
| 微信有**多个进程** | 「未找到 Weixin.dll」→ 热激活失败 | 只有主窗那个进程带 `Weixin.dll`；用 `tools\uia-diag.py --all` 确认 |
| 微信版本**不在库的版本表** | 走特征扫描兜底，升级后可能失效 | `uia-diag.py` 会打印「版本表命中 / 特征扫描」；失败先重启微信再试 |
| `Copy-Item -Recurse` 到已存在目录 | 生成 `src\src`、`web\web`，新文件藏进去 | 同步只用 `scripts\deploy.ps1`（robocopy + 哈希校验） |
| PowerShell 解析中文 `.ps1` | 报「Missing ')'」「字符串缺少终止符」 | `.ps1` 必须存成**带 BOM 的 UTF-8**（测试里有断言） |
| 打包时从错的目录取文件 | 源码改了、包里是旧的（3.0.3 事故） | 只用 `build-release.ps1`；它出包后会从 zip 里读文件复核 |
| 测试会写真文件 | `providers.test.js` 曾把真实 `data/settings.json` 覆盖 | `loadConfig` 必须传 `{ root, env }`；测试只用临时目录 |

## 数据与隐私

- `data\`（含 `settings.json` 的 Key、`store.json` 的聊天记录）、`config.json`、`wechatauto_db\`、`wechatauto_logs\` **永远不进包**，`.gitignore` 已排除，`release-check --release` 会再查一遍。
- 发布前扫一遍个人信息（`release-check.js` 已自动做，共 3 类）：① `sk-` 开头 16 位以上的密钥；② `wxid_` 开头的真实 wxid（占位符 `wxid_xxx` 不算）；③ `C:\Users\` 后面跟非 ASCII 用户名。命中即视为不合格，不允许出包。

## 重置全部（恢复出厂）

`重置全部.bat` = **真的格式化**，不是重启。它按顺序做：

1. 停掉所有进程（复用 `stop-all.ps1`）
2. 把 `data\` 和 `config.json` 备份到 `backup\reset-<时间戳>\`（Key / 聊天记录还能从这里捞回来）
3. 删除 `data\`、`config.json`、`wechatauto_db\`、`wechatauto_logs\`、`debug.log`、临时截图
4. 用 `config.example.json` 重建 `config.json` —— 和刚解压时完全一样（主人名单空、令牌是 `change-me-*`）
5. 重新启动服务 + 桥接（`-NoStart` 可跳过）

保留：程序本体（`src` / `web` / `examples` / `scripts` / `runtime`）。

重置后要做的两步：
- 网页右上角「设置」重新填 API Key（看图 Key 也要重填）
- 主人名单为空：去 `/debug` 的「最近说过话的人」抄自己的 `wxid_xxx` 填回 `config.json`

命令行（脚本化/自检用）：`powershell -File scripts\factory-reset.ps1 -Yes -NoStart`

## 版本规则：一个改动 = 一个版本号

三档语义（`npm run bump` 默认 patch）：

| 改动类型 | 用哪个 | 例子 |
| --- | --- | --- |
| 修 bug / 文案 / 小调整 | `patch` | 3.0.15 → 3.0.16 |
| 新功能、可见行为变化 | `--level=minor` | 3.0.16 → 3.1.0 |
| 不兼容的大改（配置格式、目录结构） | `--level=major` | 3.1.0 → 4.0.0 |

**版本号必须在台面上看得见**（3.1.0 起）：
- 包名带完整版本：`whale-girl-3.1.0.zip` / `whale-girl-3.1.0-full.zip`，解压出来的文件夹也叫 `whale-girl-3.1.0`
- 服务启动横幅：`版本： v3.1.0`
- 网页标题下面的状态栏：`… · v3.1.0`
- `/api/status` 的 `version` 字段

改动落地的固定流程（缺一不可）：

1. `npm run bump -- "这次改了什么"` —— 版本号 +1，并在 CHANGELOG 顶部插一条（`--level=minor|major` 用于大改动）
2. `npm test` —— 全量测试
3. `npm run release-check` —— 自检（会强制校验：版本号不重复、不跳号、每条都有内容、`package.json` = CHANGELOG 首条）
4. `scripts\deploy.ps1 -Target <运行目录> -Restart` —— 部署并重启
5. `scripts\build-release.ps1` —— 出包（出包时会从 zip 里读文件复核）

硬性约束（已由 `release-check.js` 自动拦截）：

- 同一个版本号只能对应一次改动，**不允许**改完又拿同一个号再改一次
- 补丁号必须连续：`3.0.15` 之后只能是 `3.0.16`，不能跳号
- 每个版本都必须有说明内容，不能只有标题
- `package.json` 的版本必须等于 CHANGELOG 的第一条

历史遗留：`2.9.2` 是从上游接手的起点，它前面没有 `2.9.0/2.9.1`，所以连续性是按**当前版本线**（`3.0.x`）检查的。
