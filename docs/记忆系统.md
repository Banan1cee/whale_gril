# 记忆系统（4.0 / v2）

一句话：**一个静态人设 + 每个聊天里的「一人一卡」+ 每个聊天的事件时间线 + 当前话题的短期缓冲。**

- 设计规格：`docs/memory-v2-spec.md`
- 实现：`src/memory/*`
- 没有全局用户记忆，没有跨聊天同步，没有敏感词分类，用户看不到任何记忆正文。

---

## 1. 硬约束

1. 按聊天隔离：私聊 A、群 G、群 H 各自独立物理目录。
2. 按人建卡：卡的主键是 `chatId + uid`，不是全局用户。
3. 群聊只读当前说话人：A 说话只注入 A 的卡，B 问 A 也不注入 A 的卡。
4. 写卡必须满足 `card.chatId === source.chatId`，不一致直接抛
   `MEMORY_CHAT_MISMATCH`，不做自动合并。
5. 不做敏感词分类、不做敏感字段、不做输出审查。
6. 记忆不展示、不提供查询接口：`GET /api/memory` 已删除，启动器记忆页已删除，
   聊天里的 `/memory` 命令已删除；调试台只显示计数。

---

## 2. 四层

| 层 | 内容 | 作用域 | 生命周期 |
|---|---|---|---|
| L0 | 鲸鲸人设 | 全局静态 | 永久，聊天不改写 |
| L1 | 人物卡（traits + preferences） | `chatId + uid` | 长期 |
| L2 | 事件卡 + threads | `chatId + uid` | 365 天 / 200 条每人 |
| L3 | 当前 episode 原文 + 摘要 | 当前 chat | episode 关闭时清空缓冲 |

```text
private:A card(A) ≠ group:G card(A) ≠ group:H card(A)
```

---

## 3. 存储布局

```text
data/memory/
├─ manifest.json
├─ legacy/                    # 迁移前的旧文件只读副本（程序不再读）
└─ chats/
   └─ <chatHash>/             # sha1(chatId).slice(0,16)
      ├─ meta.json            # chatId、平台、state、episode、closedEpisodes
      ├─ people/
      │  └─ <personHash>.json # sha1(uid).slice(0,16)
      ├─ messages.jsonl       # 原文，追加写
      ├─ summary.json         # 当前摘要段 + coveredThroughSeq
      └─ checkpoints/
         └─ 00000123.json     # 每轮一份，最多 50
```

- 卡片 / 摘要 / checkpoint：先写 `.tmp` 再 `rename`。
- 用户消息先 `fsync` 落盘，再进入回复流程；回复失败也不丢用户消息。
- 每个 chat 的磁盘写入是同步串行的；跨 chat 后台任务按 chat 排队。
- 原文只追加；只有「已被 summary 覆盖」且超过 90 天 / 2000 条的旧消息才会删。

---

## 4. 写入

每条消息：

```text
1. 识别 chatId + uid
2. 追加 messages.jsonl（用户消息 fsync）
3. 更新 meta.lastActiveAt / stats / episode 计数
4. 规则抽取（不调模型）：明确自述、明确纠正、手动记住
5. 连续 20 条 user 消息 → 轻量 fact 候选（不调模型、不写 L2）
6. 软阈值 2,400 token → 后台准备「最旧 800 token」摘要
7. 进入回复流程
```

episode 关闭（任一条件）：

- 空闲 30 分钟；
- 聊了至少 6 条后话题切换（关键词重合度 < 0.15，或明确说「换个话题」）；
- 累计 6,000 token；
- 持续 3 小时。

关闭时：生成最终摘要 → 给每个发言人写一条 L2 → 抽 fact / trait / thread →
重置 L3 水位 → 新 episode 从下一条消息开始。同一个 `episodeId` 只写一次。

性格标签比事实谨慎：至少 2 条证据（或明确自述）、`confidence >= 0.65`、
必须带消息 id；单次情绪、玩笑、反话不写。

---

## 5. 读取

每轮回复只加载：

```text
当前 chat 里、当前说话人的卡
  → traits + preferences（≤900 token 预算内）
  → 这个人事件卡里 top 3~5（bigram + BM25 + recency/importance/confidence + MMR）
  → 当前摘要
  → 最近原文（≤3,200 token，当前消息永不裁剪）
```

记忆块放在**最后一条 user 消息**里，不塞 system：system 会话内稳定，前缀缓存不被打断。
群聊历史是公开的，可以用；但 A 的私聊卡、A 在别的群的卡永远不进来。

---

## 6. 压缩与预算

```text
recent >= 2,400  → 后台准备摘要（不删消息）
recent >  3,200  → 应用摘要，移走最旧 800，回到 2,400
summary > 900    → 合并最旧摘要段（保留每段开头），不直接丢事实
```

压缩只影响 prompt 缓冲，不删 `messages.jsonl`。摘要失败时原文保留、
`coveredThroughSeq` 不前进。

预算语义（2026-10 调整）：

```text
dialogueBudget       = 5,500 = memory 900 + summary 900 + recent 3,200 + reserve 500
systemTokens         = estimateTokens(system)      # 只测量，不裁剪
estimatedInputTokens = systemTokens + dialogueBudget
hardTotalTokens      = 32,000                      # 超过才拒绝/报错
```

- 不再有「7,500 总预算 / 2,000 system 上限」。
- system 变大不会挤 recent 或 memory。
- token 估算：CJK ≈0.65/字、非 CJK ≈0.3/字、每条消息 +4；预算裁剪乘 1.08。
- **人设保存 / 导入**时用当前模型的官方 tokenizer（服务商 `usage.prompt_tokens`）精确校验；
  上限 = `32,000 - 5,500 = 26,500`。没有 Key / 离线时退回估算并标 `exact:false`。
  每轮聊天仍然只用轻量估算，不调官方 tokenizer。
- API usage（`prompt_tokens` / `completion_tokens`）会记录并与估算对比，
  误差 >15% 记 warning。只记计数，不打印正文。
- 只给内部 status / 日志字段，不做预算 UI、滑块、接口。

---

## 7. 关闭 / 重启 / 迁移

- 正常关闭：flush 消息队列 → 写最后一个 checkpoint → 关文件。
- 启动：读 meta / 卡 / summary → 读最近原文 → 距上次消息 >30 分钟则后台补写
  上一个 episode 的 L2 → `recent >3,200` 时首条回复前压缩。
- 不会全量重压；原文已经落盘，补写失败只是晚一轮。

迁移（4.0 `store.json` + journal、旧 `memory.json`）：

- 每个旧会话 key 落到自己的 chat 目录，绝不跨 chat 合并；
- 旧 notes 标 `legacy: true`、置信度 0.4（等新对话纠正/加强）；
- 旧文件不删、不改；在 `data/memory/legacy/` 留只读副本和说明；
- 幂等：`manifest.migratedFrom` 记源文件大小 + mtime，重复启动不会重复导入。

备份 / 恢复只保留本地 CLI 和本地文件（`scripts/memory-tool.js`、
`data/backups/`）；没有 HTTP 接口，不在 UI 展示正文。

## 8. 参数

全部写死在 `src/memory/constants.js`，不读 `config.json`、不提供接口。

| 参数 | 默认值 |
|---|---:|
| `dialogueBudget` | 5,500 |
| `hardTotalTokens` | 32,000 |
| `memoryTokens` | 900 |
| `summaryTokens` | 900 |
| `recentMaxTokens` | 3,200 |
| `recentLowTokens` | 2,400 |
| `compressChunkTokens` | 800 |
| `reserveTokens` | 500 |
| `episodeMaxTokens` | 6,000 |
| `episodeIdleMinutes` | 30 |
| `episodeMaxHours` | 3 |
| 每人 traits / preferences / events / threads | 12 / 30 / 200 / 10 |
| 每 chat 人数 / events | 50 / 1,000 |
| 原文保留 | 2,000 条 / 90 天 |
| 事件保留 | 365 天 |
| 输出上限 | 普通 100 字 / 讨论 400 字 |

## 10. 已知限制

1. token 是轻量估算，不接 tokenizer；用 API usage 校准，误差 >15% 会告警。
2. episode 关闭后的第一轮靠摘要接住旧话题；摘要生成失败时只会少一段摘要，
   原文仍在磁盘。
3. 群聊里事实按「说话的人」归，不按「关于谁」归；B 问 A 的私事，只有群历史
   公开部分可用。
4. 记忆仍在本机 `data/memory/` 文件里；能直接翻文件的人还是能看到，
   应用界面不暴露。
