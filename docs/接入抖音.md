# 接入抖音

> 先说结论：**抖音没有公开的「群聊机器人」API**。  
> 想在抖音上和「鲸鲸」互动，现实里有三条路：企业号私信（官方、要资质）、直播弹幕（官方开放能力或开源抓取）、第三方中转服务。  
> 每条路都有门槛或风险，下面把可行做法和坑都列清楚。

---

## 三条路

| 路线 | 能做什么 | 需要什么 | 风险 |
| --- | --- | --- | --- |
| ① 企业号私信（官方） | 用户私信自动回复、客服式对话 | 企业号 / 服务商资质，开放平台应用 | 低（官方），但审核门槛高 |
| ② 直播弹幕（官方开放能力） | 直播时读弹幕、互动 | 开放平台「直播互动」能力资质 | 低（官方），但只对特定开发者开放 |
| ③ 直播弹幕（开源抓取） | 读直播间弹幕、发评论 | 登录 cookie、开源工具 | 中～高，违反平台协议、账号受限 |
| ④ 第三方客服/中转系统 | 私信、评论、群消息托管 | 服务商账号 | 看服务商，通常收费 |

不管哪条路，**鲸鲸这侧只认一个 webhook**：`POST /webhook/douyin`，协议和微信完全一样（见 [GATEWAY.md](GATEWAY.md)），只是 `platform` 换成 `douyin`。

---

## 路线一 / 四：企业号私信（官方或中转）

抖音开放平台的 IM 能力会把用户私信通过**回调**推给服务端（通常还需要服务商/应用审核）。

### 配置

`config.json`：

```json
{
  "gateway": {
    "douyin": {
      "enabled": true,
      "inboundToken": "换成你自己的随机字符串",
      "outboundUrl": "https://你的服务商/api/message/send",
      "outboundHeaders": { "Authorization": "Bearer 服务商给的token" }
    }
  }
}
```

重启服务，然后在服务商后台 / 开放平台后台把消息回调填成：

```
http://你的地址:8787/webhook/douyin?token=换成你自己的随机字符串
```

抖音官方 IM 回调的 JSON 字段和我们的不完全一样，需要一个几十行的**字段转换**（把 `data.open_id` → `user_id`、`data.content` → `text` 之类）。  
转换脚本可以照抄 `scripts/mock-gateway.js` 的写法：收到回调 → 组装成我们的格式 → POST 到 `/webhook/douyin` → 把返回的 `reply` 用服务商的发消息接口发出去。

### 先本地联调

```bash
# config.json 里 gateway.douyin.enabled 改成 true 并重启
node scripts/mock-gateway.js --platform=douyin --text="鲸鲸在吗" --user=海胆酱
node scripts/mock-gateway.js --platform=douyin --private --text="在吗"
```

## 路线二：官方直播互动能力

抖音开放平台有面向游戏/小玩法的「直播互动」能力，可以把弹幕事件推给服务端（需要申请资质）。

拿到推送后，把它转成我们的格式：

```json
{
  "chat_id": "live_房间号",
  "chat_type": "group",
  "user_id": "open_id",
  "nickname": "小丑鱼",
  "text": "鲸鲸你在吗",
  "msg_id": "弹幕消息id",
  "at_me": false
}
```

POST 到 `/webhook/douyin`。回复要发回直播间，用开放平台对应的评论接口（同样需要资质和 token）。

## 路线三：开源工具抓直播弹幕（不推荐，仅供研究）

社区里有抓抖音直播弹幕的开源项目（搜索关键词：`DouyinLiveWebFetcher`、`dy-live`、`抖音弹幕`），原理是带登录 cookie 连直播间的 WebSocket。

大致流程：

```
开源抓弹幕工具 ──(弹幕 JSON)──> 你的小脚本 ──POST──> 鲸鲸 /webhook/douyin
                                                        │
直播间评论接口 <──(登录态)───────────────────────────────┘
```

示意脚本（Python，需要你自己装依赖并填 cookie，**未在本项目里验证**）：

```python
import requests

BOT = "http://127.0.0.1:8787/webhook/douyin"
TOKEN = "换成你自己的随机字符串"

def on_danmaku(user, content, room_id, msg_id):
    r = requests.post(
        BOT,
        params={"token": TOKEN},
        json={
            "chat_id": f"live_{room_id}",
            "chat_type": "group",
            "user_id": user.get("id", "unknown"),
            "nickname": user.get("nickname", "观众"),
            "text": content,
            "msg_id": msg_id,
        },
        timeout=60,
    )
    data = r.json()
    if data.get("action") == "reply":
        return data["reply"]      # 交给你的发评论逻辑
    return None
```

> 这类工具依赖登录 cookie、随时可能失效，且**违反平台协议**，账号可能被限制。请只做技术研究，不要用于引流、刷屏、带货等场景。

## 抖音这侧的三个建议

1. **别用主账号**。抓弹幕/自动回复都有风控，用小号或测试直播间。
2. **频率要低**。直播间弹幕量很大，别每条都回。建议只回被 @ 或者提到「鲸鲸」的弹幕，并设冷却（默认规则已经这样）。
3. **回复要短**。直播间里长段文字没人看，默认群聊长度上限 80 字，够用。

## 常见问题

**Q：能不能像 QQ 群那样把机器人拉进抖音群？**  
A：目前没有公开的「抖音群机器人」能力。群里互动只能通过企业号/服务商体系，或者你自己抓协议（有风险）。

**Q：弹幕工具抓到的消息怎么区分是不是 @ 她？**  
A：直播弹幕一般没有 @ 概念，把含「鲸鲸 / 鲸鲸 / 小鲸」的弹幕当成呼叫即可（本程序会自动识别名字）。也可以在转换脚本里把 `at_me` 设成 `true`。

**Q：抖音和微信的群会串记忆吗？**  
A：不会。记忆按「平台 + 聊天 id」分开存。

**Q：同一个中转服务能同时接微信和抖音吗？**  
A：可以，本程序两个 webhook 是独立的，各自配 token 和 outboundUrl。
