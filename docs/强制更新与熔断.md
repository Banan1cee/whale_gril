# 强制更新与熔断

> 一句话：客户端每次启动读 `release-manifest.json`，按里面的策略决定「提不提示 / 强不强制 / 让不让启动」；你改那个文件就能刹车，不需要发版。

## 文件在哪

| 文件 | 谁写 | 干什么 |
| --- | --- | --- |
| `release-manifest.json`（仓库根） | **自动**（CI 发版时覆盖 `latest`/`released_at`/`manifest_version`）+ 你手填策略字段 | 唯一事实源 |
| `scripts/make-manifest.ps1` | 不常改 | 生成器：读旧文件当模板，覆盖变动字段 |
| `launcher/UpdateManifest.cs` | 不常改 | 客户端：多源拉取 + 判定 + 缓存 |
| `.github/workflows/installer.yml` | 不常改 | tag 时生成、传 Release 资产、commit 回 main |

**你要改的东西只有一个：`release-manifest.json` 里的策略字段。**

## 字段说明

```json
{
  "latest": "4.0.7",
  "released_at": "2026-11-06T18:10:07Z",
  "force_after_hours": 12,
  "force": false,
  "kill_below": null,
  "message": "更新说明，会显示在弹窗里",
  "manifest_version": 1,
  "channel": "stable"
}
```

| 字段 | 谁管 | 含义 |
| --- | --- | --- |
| `latest` | 自动 | 最新版本号，决定「有没有新版」 |
| `released_at` | 自动 | 这一版的发布时间，时间闸从这里开始算 |
| `manifest_version` | 自动 | 每次发版 +1；客户端多源取值时只认最大的（防旧缓存 / 防回放） |
| `force_after_hours` | **你** | 发布满这么多小时才强制。12 = 半天 |
| `force` | **你** | `null`=按时间闸自动；`true`=立即强制；`false`=只提示（刹车） |
| `kill_below` | **你** | 低于这个版本直接不许启动；`null`=不熔断 |
| `message` | 半自动 | 自动填「更新到 vX」；手写成别的文案会被保留 |
| `channel` | 你 | 预留，目前固定 `stable` |

## 客户端怎么判

按顺序，命中即停：

```
本机版本 >= latest                  → 正常，不提示
本机版本 <  kill_below              → 禁止启动（弹说明后退出）
force === true                      → 强制（只有「立即更新 / 退出」）
force === false                     → 只提示（可以点「以后再说」）
now - released_at >= force_after_hours → 强制
否则                                 → 只提示
```

几条兜底规则，别改：

- 清单一个源都拿不到 → 用本地缓存（`%LOCALAPPDATA%\WhaleGirl\update-state.json`）
- 连缓存都没有 → **放行**，不拦人
- JSON 解析异常 / 字段缺失 → 降级成「只提示」
- 本机版本号读不出来 → 放行

## 日常发版：你什么都不用改

```powershell
npm run bump -- "修了 XXX"
npm test
npm run release-check
git push origin main
git tag v4.0.7
git push origin v4.0.7
```

CI 会自动：生成 manifest → 挂到 Release 资产 → commit 回 main。

用户那边：发布后 12 小时内只看到提示，满 12 小时后启动就会被要求更新。

## 三种救火操作

**用命令改，别手改。** 命令会自动把 `manifest_version` +1——这一步不能省，否则 Release 资产里那份同序号的旧清单会盖过你的改动，刹车直接失效。

```bash
npm run brake                          # ① 刹车：只提示，不强制
npm run force-now                      # ③ 立即强制所有人升
npm run unbrake                        # 改回去：按时间闸自动

node scripts/manifest-policy.js --kill-below 4.0.7     # ② 熔断：低于 4.0.7 不许启动
node scripts/manifest-policy.js --kill-below null      # 取消熔断
node scripts/manifest-policy.js --force-after-hours 6  # 调时间闸
```

改完 `git commit + push`，客户端 1~5 分钟内生效。

**万一手改**，必须同时把 `manifest_version` +1：

```json
"force": false,
"manifest_version": 3    // 原值 2 就写 3
```

## 升版本号

| 想升到 | 命令 |
| --- | --- |
| 4.0.7（修 bug） | `npm run bump -- "说明"` |
| 4.1.0（加功能） | `npm run bump -- "说明" --level=minor` |
| 5.0.0（改配置格式） | `npm run bump -- "说明" --level=major` |

然后 `git tag v4.1.0 && git push origin v4.1.0`。`release-manifest.json` 的 `latest` 由 CI 自动填，不用管。

## 为什么是「时间闸」而不是「stable 标签」

一个版本发布后 12 小时没人报问题，它就从「未验证」变成「可用」——代码一个字没改，是时间让它变稳的。

项目没有 beta 用户，所有用户都是第一批，所以只能让时间替我们试。连续发版时 `released_at` 会一直重置，等于「我还在改，先别踹人」。

## 首发建议

4.0.1 第一次带这套机制，**先别开闸**：

- 保持 `"force": false`
- 观察几天：是否有人反馈看到新版本提示、断网启动是否正常、版本比较有没有出错
- 确认无误后改 `"force": null`，闸门才真正打开

理由：强制逻辑本身也没被验证过。万一解析出错导致全员启动不了，连发修复版的机会都没有。

## 已知边界

- 只有**从 4.0.1 开始装的用户**受这套机制约束；之前 zip 时代的用户走 `scripts\update.ps1`，与此无关
- 用户改 hosts / 完全断网 → 只能 fail-open 放行，无法强制
- `latest` 必须与 `package.json` 一致，CI 会校验 tag；对不上会直接红
