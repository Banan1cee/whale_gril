# 设置说明（config.json 全字段）

鲸鲸有两份「设置」：

| 文件 | 谁在改 | 改了怎么生效 |
| --- | --- | --- |
| `config.json` | 你手动编辑（记事本 / VSCode 都行） | **存盘即生效**，服务会自动重新加载，不用重启 |
| `data/settings.json` | 网页右上角「⚙️ 设置」自动写入 | 保存后立刻生效（优先级比 config.json 高） |

优先级：`data/settings.json` > `config.json` > 程序里的默认值。
所以网页里填过 API Key、选过模型之后，config.json 里的 `deepseek` 段就不再起作用了（Key 存在 settings.json 里更安全）。

> 微信桥接（`examples/wechatauto_bridge.py`）是**独立进程**：改 `wechat` 段之后要重启「启动微信桥接.bat」。

以 `_` 开头的键（比如 `_说明`）只是写给人看的注释，程序会忽略。JSON 不支持 `//` 注释，所以用这种方式。

---

## 模型

| 字段 | 说明 |
| --- | --- |
| `provider` | `deepseek` / `zhipu` / `siliconflow` / `qwen` / `tju` / `ollama` / `custom`。本地地址（127.0.0.1、192.168.*）自动免 Key |
| `deepseek.*` | 老版本配置，现在一般不用动；Key 建议在网页里填（写进 data/settings.json） |

### 接本地模型（Ollama / LM Studio / vLLM / 自建接口）

任何 OpenAI 兼容接口都能接。地址填**本机或内网**的（`127.0.0.1`、`localhost`、`10.*`、`192.168.*`、
`172.16~31.*`、`host.docker.internal`、`*.local`）时：

- **不用填 Key**，网页里 Key 一栏会显示「不需要」，演示模式会被自动关掉（本地接口没有「没 Key」这回事）；
- 地址可以只写 `127.0.0.1:11434/v1`，`http://` 会自动补上；
- 地址里的 `/v1` 少了也能用（比如只写 `http://127.0.0.1:11434`），程序发现 404 会自动换
  `/v1/chat/completions` 再试一次。

常见地址：

| 服务 | 地址 | 模型名举例 |
| --- | --- | --- |
| Ollama | `http://127.0.0.1:11434/v1` | `qwen2.5:7b` |
| LM Studio | `http://127.0.0.1:1234/v1` | `qwen2.5-7b-instruct` |
| llama.cpp server | `http://127.0.0.1:8080/v1` | 跟启动参数 `-a` 一致 |
| vLLM | `http://127.0.0.1:8000/v1` | 部署时指定的模型名 |

> 局域网里另一台机器跑模型时，把 `127.0.0.1` 换成那台机器的 IP；服务本身要监听 `0.0.0.0`（
> 例如 `ollama serve` 默认只听本机，需要设 `OLLAMA_HOST=0.0.0.0`）。

## 人设 persona

| 字段 | 说明 |
| --- | --- |
| `name` | 她的名字 |
| `aliases` | 她的外号，群里有人喊这些也算叫她 |
| `ownerName` | 她叫你什么（默认「主人」） |
| `master.names` / `master.wxids` | **主人名单**：`names` 填微信昵称，`wxids` 填 `wxid_xxx`（微信内部 id，**不是**你自己设置的微信号，比如 `abc12345` 那种自己设的微信号）。谁填谁就是主人；留空 = 没有主人。微信里**只认 wxid**：一旦 `wxids` 里有一个像 `wxid_` 开头的值，改昵称冒充就不管用了；`wxids` 全空时才退回按昵称认。不知道自己 wxid？打开调试台 http://127.0.0.1:8787/debug ，「身份 / 主人」卡片里有「最近说过话的人（真实 senderId）」，照抄即可 |
| `masterRoast` | 主人骂她时能不能还嘴（默认 `false`：只委屈不骂回去） |
| `appearance` / `personality` / `background` | 外貌 / 性格 / 背景设定，会进系统提示词 |

## 聊天 chat

| 字段 | 说明 |
| --- | --- |
| `privateMaxChars` | 私聊每条最多几个字 |
| `groupMaxChars` | 群聊每条最多几个字 |
| `maxBubbles` | 一次最多连发几条（像真人分几条发） |
| `historyTurns` / `groupHistoryTurns` | 带多少轮历史 |
| `discussionMaxChars` | 让她「分析一下」时的长度上限 |
| `emojiChance` | 带 emoji / 颜文字的概率。**留 0 = 跟着调教台「颜文字用量」自动算**：关 0% / 少 12% / 正常 30% / 多 65%；填 0.2 就强制两成（「关」档位仍然压过它） |

## 群聊 group

| 字段 | 说明 |
| --- | --- |
| `requireAt` | `true` = 只有 @ 她 / 叫她名字才回复 |
| `freeChat` / `freeChatChance` | 允不允许她偶尔主动接话，概率多少（0.06 = 6%） |
| `cooldownSec` | 两次回复最少隔几秒 |
| `masterAlwaysReply` | 主人在群里说话永远回 |
| `engagedMinutes` | 她接话后保持参与多少分钟 |
| `silentMinutes` | 冷场多久算这个话题结束 |
| `maxRepliesPerHour` | 每小时最多回几条（防刷屏） |
| `muteDefaultMinutes` | 免打扰默认时长（分钟） |

## 记忆 memory

`maxSessions` 最多记几个会话、`maxMessages` 每个会话多少条、`maxNotesPerUser` 每人几条笔记。

## 魔咒 admin

`spell` 填一段口令（比如 `0420`），主人私聊或群里发了它就临时获得管理员权限，`minutes` 是有效期；`allowAll: true` 时谁发都行。留空 = 关闭。

## 主动分享 share

`enabled` 开关、`everyMinutes` 每隔多少分钟分享一次、`sources` 来源（目前 `bilibili`）。

## 消息汇总 digest

调试台「功能开关」中，**消息汇总**一行直接提供总开关和「每隔（分钟）／保存间隔」。默认关闭，只有 `digest.enabled` 这一个真源；`everyMinutes` 为1～1440分钟整数，默认30。改动自动生效，不必重启。

- 关闭：不采集、不轮询、不推送，接口404；清空本轮待汇总内容，再打开只收新消息。
- 开启：只节选微信中未接话的普通消息，不收已回答的、重复的、主人消息、系统通知或网页测试聊天；每次文本有限长及省略提示。这是消息节选，不是模型生成的事实总结。
- **接收人必须在主人设置中填写唯一明确的微信内部ID**（`persona.master.wxids`）。只填昵称或设置多个接收人时不推送，避免重名发错人。消息发送仍受账号、前台、会话标题和草稿安全检查约束。
- 本轮队列不落盘；服务重启不回放以前的汇总。不确认发送成功的任务不自动重试，以免重复发送。
- 原来的游戏检测、离开／回来通知、忙时排队补发、群成员发言次数排行已删除；旧配置键即使留在个人配置中也不会起作用。

## 微信桥接 wechat

| 字段 | 说明 |
| --- | --- |
| `staleAfterSec` | 多久没新消息就当她「去忙了」 |
| `quoteReply` | 是否引用原消息回复 |
| `lowBatteryPercent` | 笔记本电量低于几 % 说晚安 |
| `ignoreSenders` | 这些会话永不回复（微信团队、订阅号等） |
| `goodnightText` | 电量低时的告别语 |
| `account` | **固定用哪个微信号**。微信双开 / 多账号时必填，填账号目录名、`wxid_xxx` 或微信昵称都行；留空 = 按「最近活跃」自动选（双开时可能选到大号）。一般不用手改：双击「启动鲸鱼娘.bat」启动后，在自动打开的浏览器页面右上角点「⚙️ 设置」→「微信账号」，选一下就会写这里（**不是微信自己的设置**） |
| `accountGuard` | 默认 `true`：认不出「哪个微信窗口是所选的号」时就**不发**（宁可不回，也不能从大号发出去）。本机只登一个号时它不起作用 |
| `windowHwnd` | 调试用：手动钉住微信主窗句柄，`0` = 自动识别 |

### 微信双开：怎么固定用小号

1. 大号、小号都登着微信（任务栏会有两个「微信」窗口）。
2. 双击 `启动鲸鱼娘.bat`，打开网页 → 右上角 **⚙️ 设置** → **微信账号（双开时必选）**。
3. 下拉里会列出本机所有微信账号（昵称 · wxid · 最近活跃），选**小号** → 保存。
4. 桥接会在几秒内自己重启，日志里会出现「指定账号：wxid_xxx_xxxx」和「账号窗口已确认」。
5. 想确认现在到底用的哪个号：设置里那行会写「桥接当前在用：xxx（窗口已确认）」；`/debug` 调试台也能看到。

> 如果日志出现「认不出账号窗口」「没发送」，说明微信窗口没能和这个号对上——这时她**故意不发**，
> 免得从大号把消息发出去。把微信窗口从托盘里拉出来、别只留一个号在屏幕外，再重启桥接即可。

## 网关 gateway（方案B，可不用）

本地桥接**不需要** `outboundUrl`：回复直接写在 POST `/webhook/wechat` 的响应里。
`inboundToken` 必须和桥接脚本读到的值一致，否则服务端返回 401，表现为「她收到了但不回」。

## 其它

- `links`：别人发链接时读不读标题/摘要/正文。
- `log.level`：`debug` / `info` / `warn` / `error`，日志在 `data/whale.log`。
- `vision`：看图说话（默认智谱 GLM-4V-Flash，免费额度够用）。Key 的填法有三种，按优先级：
  1. 网页右上角「设置」→「看图 API Key」（存进 `data/settings.json` 的 `visionApiKey`，**推荐**；旁边有「测试看图」按钮可以先测再存）
  2. `config.json` 的 `vision.apiKey`
  3. 什么都不填时，会自动沿用 `data/settings.json` 里存过的**智谱** Key（用智谱聊天的话同一把就能看图）

  注意：**DeepSeek 的 Key 不能看图**（官方没有视觉接口）。报「令牌已过期或验证不正确」基本都是把 DeepSeek 的 Key 填到了这里。

  还需要 **ffmpeg**：微信 4.x 的图片是 wxgf（HEVC 容器），要靠 ffmpeg 转成 JPEG。桥接启动时会自动在 C:\ffmpeg\bin、untime\ffmpeg\bin 等位置找，日志里会打印「找到 ffmpeg：…」；找不到就会提示「没找到 ffmpeg」。装法：把 ffmpeg 解压到 C:\ffmpeg（保证有 C:\ffmpeg\bin\ffmpeg.exe）后重启桥接。

  长截图（高宽比 > 2.2）会自动切成 2~3 段分别识别再拼接；单次输出上限受模型限制（智谱 GLM-4V 是 1024 tokens，可在 ision.maxTokens 调整）。
- `voice`：语音转文字（默认阿里云百炼 qwen3-asr-flash）；`maxSeconds` 超过多少秒的语音不转。
- `server`：网页地址与端口（改了要重启服务）。

## 常见问题

**改了 config.json 没反应？**
1. 看 `data/whale.log` 有没有 `config.json 已重新加载`；
2. 如果出现 `config.json 改了但没读成功`，说明 JSON 写坏了（多半是少了逗号 / 多了逗号），照着提示的行号修；
3. `server.port`、`server.host` 这类启动参数仍然要重启才生效。

**网页里的设置和 config.json 冲突？**
网页里保存过的（模型、Key、温度、群聊 requireAt / freeChat / 概率、怎么称呼你）存在 `data/settings.json`，它会盖掉 config.json。想让 config.json 说了算，就把 `data/settings.json` 里对应的键删掉。

## 在调试台里直接改所有设置（推荐）

打开「打开调试台.bat」→ 页面顶部就是「全部设置」卡片，config.json 里的每一个字段都在这里，改完点「保存修改」。

- 保存后**立即生效**，不用重启（`server.port` / `server.host` 除外）。
- 保存会写回 `config.json`（保留 `_说明` 注释行、保持 UTF-8），同时把 `data/settings.json` 里会盖住这个字段的旧值删掉——所以不会出现「网页上改了却不生效」。
- 输入框旁边的灰字是这一项的说明；开关类直接点，列表类一行一个，`outboundHeaders` 这种填 JSON。
- 密钥（DeepSeek Key、视觉/语音 Key、gateway 的 inboundToken）显示为「已设置（留空 = 不改）」，不填就不会动它。
- 改了还没保存时，字段会标黄，保存按钮会变成「保存修改（N 项）」；「撤销」丢弃改动，「重新读取」从磁盘重读。

## 主动搭话 care

没事的时候她自己来找你说句话（问「在干啥」「累不累」），机制和「主动分享视频」一样：
桥接定时问服务端「该不该发」，服务端算时间窗和频率，桥接负责挑个不在聊的会话发出去。

| 字段 | 说明 |
| --- | --- |
| `enabled` | 总开关 |
| `windows` | 允许搭话的时间段，一行一个，24 小时制：`09:00-12:00`、`14:00-23:00`；跨零点写 `22:00-02:00` 也认；留空 = 默认 `09:00-23:00` |
| `everyMinutes` | 平均多久一次（分钟） |
| `jitterMinutes` | 前后随机浮动，避免准点得像机器人（`25` = 在 65~115 分钟之间） |
| `maxPerDay` | 每天上限，`0` = 不限 |
| `quietAfterMinutes` | 这个会话在这么多分钟内有过消息，就先不打扰 |

调试台（`/debug` → 「主动找你聊天」）里可以直接改这几项；改完**要重启「启动微信桥接.bat」**才生效
（桥接在启动时读一次配置）。

判断逻辑在 `src/care.js`，服务端两个接口：
- `GET /api/care/due?last=<毫秒>&sentToday=<次数>` → `{due, reason, waitMinutes…}`
- `GET /api/care?chat=<会话 id>` → `{text}`（带最近聊天上下文生成；没配 Key 时用内置台词）
