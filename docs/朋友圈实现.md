# 朋友圈：读、赞、评论、发布（Windows 微信 4.x）

> 依赖：`wechatauto-replica`（PyPI 包名，导入名 `wechatauto`）+ Python 3.12。
> 定位：**实现依据**。每章开头先给「能不能自动化」的结论，代码可直接抄进项目。
>
> **风险速览**
>
> | 功能 | 是否碰界面 | 能否自动化 | 账号风险 | 技术失效风险 |
> | --- | --- | --- | --- | --- |
> | 读 | 否（纯数据库） | ✅ 可以 | 接近零 | 中（依赖解密实现） |
> | 赞 | 是（UIA） | ⚠️ 谨慎 | 中 | 中 |
> | 评论 | 是（UIA） | ⚠️ 谨慎 | 中 | 中 |
> | 发布 | 是（坐标） | ❌ 不建议 | 高 | 高 |

---

## 一、读（数据库路线，可自动化，不抢焦点）

**结论：可以放心自动化。不操作界面、不发网络请求，微信感知不到。**

### 1.1 技术原理

微信 4.x 的朋友圈数据存在 `sns.db`，它是 **SQLCipher 4 加密的 SQLite**。
`WeChatDB` 通过读取微信进程内存拿到解密密钥（`ReadProcessMemory`，只读权限），
解密后 `MomentDB` 直接查 `SnsTimeLine` 表；每条的 `content` 是 `SnsDataItem` XML，
从中解析正文、图片/视频 md5、点赞、评论、定位。

注意这不是「注入」：只调用 `OpenProcess(PROCESS_VM_READ)` + `ReadProcessMemory` 读数据，
没有 `WriteProcessMemory` 写代码、没有 `CreateRemoteThread` 执行，微信进程状态不变。

### 1.2 完整代码

```python
from wechatauto import WeChatDB, MomentDB


def read_moments(limit: int = 20, keyword: str = None, username: str = None):
    """读朋友圈。纯数据库，不打开朋友圈窗口。

    Args:
        limit: 返回条数；0 = 不限（配合 keyword 做全量搜索）。
        keyword: 只保留正文包含该关键词的动态（大小写敏感）。
        username: 只保留指定 wxid 发布的动态。

    Returns:
        list[dict]，字段见 1.3。

    Raises:
        RuntimeError: 微信没运行、权限不足（非管理员）、或找不到 sns.db。
    """
    db = WeChatDB()          # 需要微信客户端正在运行；桥接进程要管理员权限
    md = MomentDB(db)
    return md.get_moments(limit=limit, keyword=keyword, username=username)


def read_my_moments(limit: int = 20):
    """只读自己发的朋友圈。"""
    md = MomentDB(WeChatDB())
    return md.get_my_moments(limit=limit)
```

### 1.3 返回字段

```python
{
    "id":          "动态 id",
    "tid":         "内部 tid",
    "username":    "发布者 wxid",
    "nickname":    "发布者昵称（会查联系人库）",
    "text":        "正文",
    "location":    {"latitude": "...", "longitude": "..."} | None,
    "create_time": 1699999999,          # Unix 秒
    "images":      [{"md5": "...", "url": "...", "size": 0, "width": 0, "height": 0}],
    "videos":      [...],
    "likes":       ["昵称1", "昵称2"],   # 点赞的人
    "comments":    [...],                # 评论列表
}
```

### 1.4 注意事项

- **必须微信在运行**：密钥要从进程内存拿，微信退出就读不了。
- **必须管理员权限**：非管理员 `OpenProcess` 会失败（返回 0 密钥），表现为「读不到数据」而不是报错。
- **版本依赖**：密钥提取和 `SnsDataItem` 解析都是围绕微信 4.x 实现的。微信大版本升级可能失效，届时优先升级库，不要自己改解密逻辑。
- **过滤在 Python 侧做**：`since` / `until` / `keyword` 无法下推到 SQL（时间在 XML 里），库里用「放大拉取 + 逐条过滤」实现，大数据量时注意耗时。

## 二、赞（UIA，会打开朋友圈窗口）

**结论：可以用，但要接受「会抢前台」和「偶发失败」。**

### 2.1 完整代码

```python
from wechatauto import WeChat


def like_moment(publisher: str = None, keyword: str = None) -> tuple[bool, str]:
    """给指定朋友圈点赞。

    定位条件二选一：publisher（发布者昵称）或 keyword（正文关键词）。

    Returns:
        (是否成功, 说明文字)
    """
    if not publisher and not keyword:
        return False, "至少要给 publisher 或 keyword"

    wx = WeChat()
    resp = wx.Moment.LikeMoment(publisher=publisher, keyword=keyword)
    return bool(resp), resp.get('message', '')


def cancel_like(item) -> tuple[bool, str]:
    """取消点赞（item 必须是 GetMoments 拿到的 MomentItem）。"""
    wx = WeChat()
    resp = wx.Moment.Like(item, cancel=True)
    return bool(resp), resp.get('message', '')
```

> `WxResponse` 是 dict 子类：判断成功用 `bool(resp)`（等价 `resp.is_success`），
> 取说明文字用 `resp.get('message')`——**不是** `resp.message`。

### 2.2 内部路径与失败原因

`LikeMoment` 的流程：滚动定位到目标动态 → 点开右侧「…」→ 点「赞」。

失败基本都发生在这一步：

- **「未能定位到目标朋友圈」**：昵称/关键词没匹配上。多滚动几屏，或换成更独特的正文关键词。
- **「未能打开朋友圈操作菜单」**：「…」按钮在 UIA 树里没有名字，库靠锚点找；微信 4.x 改版后锚点可能变。
- 库里还有一条 `MomentActionMenu` 老路线做兜底，两条都失败才返回失败。

**这是 UIA 定位，不是写死坐标**——所以换个分辨率不会直接失效，但微信改版会。

## 三、评论（UIA，顺带模板匹配点「发送」）

**结论：同「赞」，但多一步「发送按钮靠模板识别」。**

### 3.1 完整代码

```python
from wechatauto import WeChat


def comment_moment(publisher: str = None, keyword: str = None,
                   content: str = "") -> tuple[bool, str]:
    """评论指定朋友圈。"""
    if not content:
        return False, "评论内容不能为空"
    if not publisher and not keyword:
        return False, "至少要给 publisher 或 keyword"

    wx = WeChat()
    resp = wx.Moment.CommentMoment(publisher=publisher, keyword=keyword, content=content)
    return bool(resp), resp.get('message', '')


def reply_comment(publisher: str = None, keyword: str = None,
                  reply_to: str = "", content: str = "") -> tuple[bool, str]:
    """回复某条评论。reply_to 是对方昵称。"""
    wx = WeChat()
    resp = wx.Moment.ReplyCommentMoment(
        publisher=publisher, keyword=keyword, reply_to=reply_to, content=content)
    return bool(resp), resp.get('message', '')
```

### 3.2 已知限制

库的官方 demo 自己写着：

> 「发送」按钮无 UIA 控件，需 pyautogui 模板识别；截图模板尚未提供，
> 该步目前会在输入完成后返回「发送按钮识别待补」。

也就是说：**评论能打开输入框、能输入文字，但最后点「发送」这一步依赖模板匹配**，
在模板补齐之前可能停在「输入完成未发送」。自己实现时建议加一步截图校验
（见第四章的校验方法），确认发送成功再返回成功。

## 四、发布（库没有 API，只能点界面，高风险）

**结论：库不提供发朋友圈接口。只能用坐标点，因此不适合作为自动化功能。**

### 4.1 为什么只能点坐标

库里只有读、赞、评论、回复评论的接口，没有「发表朋友圈」的 API。
发朋友圈的入口（右上角相机图标）在 UIA 树里不可靠，只能走坐标。

**这一节的所有坐标都是相对参照，不是绝对值。必须按 4.3 在自己的机器上量。**

### 4.2 流程（文字朋友圈）

1. 右键右上角相机图标 → 菜单选「发表文字」（左键点是「选照片或视频」）
2. 点输入框 → 粘贴文字
3. 点「发表」

### 4.3 坐标校准方法（换机器必做）

不要照抄任何数字。按下面做：

```python
import ctypes
from ctypes import wintypes

user32 = ctypes.WinDLL("user32", use_last_error=True)


def client_rect(hwnd: int):
    """拿窗口客户区的屏幕坐标 (left, top, width, height)，单位物理像素。"""
    rect = wintypes.RECT()
    user32.GetClientRect(hwnd, ctypes.byref(rect))
    origin = wintypes.POINT(0, 0)
    user32.ClientToScreen(hwnd, ctypes.byref(origin))
    return origin.x, origin.y, rect.right, rect.bottom


def calibrate():
    """打印当前窗口客户区，供你换算。"""
    hwnd = find_wechat_main_window()   # 用项目已有的 find_weixin_hwnd()
    left, top, w, h = client_rect(hwnd)
    print(f"客户区: ({left},{top}) 尺寸 {w}x{h}")
    print("量到的屏幕坐标 (sx, sy) 换算成相对值：")
    print("  dx = sx - left, dy = sy - top")
    print("  pct_x = (sx - left) / w, pct_y = (sy - top) / h")
```

量的时候：

1. 微信窗口**最大化**（和实际使用场景一致）
2. 用截图工具取目标元素的像素坐标
3. 按上面公式换算成 `dx/dy` 或 `pct`
4. **换分辨率或缩放后重新量**——不要指望自动适配

### 4.4 适配多分辨率的现实边界

微信的界面**不是等比缩放的**：会话列表宽度固定、工具栏高度固定，
只有内容区随窗口变化。所以：

- 固定尺寸控件（相机图标、按钮）：用「窗口锚点 + 固定偏移」，**不要用百分比**
- 跟随布局的元素：优先 UIA 定位，坐标兜底
- 无 UIA 名字的控件（发送按钮）：模板匹配，不是坐标

**「纯坐标 + 适配所有分辨率」在微信上做不到**。文档不承诺这一点，
能做到的是：DPI 全适配（见第五章）+ 固定元素用锚点 + 动态元素用 UIA/模板。

### 4.5 失败处理（必须做）

> 下面用到的 `find_wechat_main_window()`、`assert_moments_ui()`、`do_publish_sequence()`、
> `save_debug_screenshot()`、`verify_published()` 都是**需要你自己实现的辅助函数**，
> 库里没有。项目里可直接复用 `bridge/engine.py` 的 `find_weixin_hwnd()` 和
> `bridge/bg_sender.py` 的 `click_screen()`。

```python
def publish_text_safe(text: str) -> tuple[bool, str]:
    """发表文字朋友圈，带前置校验和失败截图。"""
    hwnd = find_wechat_main_window()
    if not hwnd:
        return False, "找不到微信主窗口"

    # 1. 前置校验：确认当前是朋友圈界面（用截图/标题判断，不要盲点）
    if not assert_moments_ui(hwnd):
        return False, "当前不是朋友圈界面，已中止"

    # 2. 执行点击序列（每个坐标都来自 calibrate()）
    try:
        do_publish_sequence(hwnd, text)
    except Exception as e:
        # 3. 失败必须截图落盘，方便复盘点了哪里
        save_debug_screenshot(hwnd, "publish-failed")
        return False, f"发布失败已截图：{e}"

    # 4. 校验：重新读一次自己的朋友圈，确认最新一条包含这段文字
    if not verify_published(text):
        save_debug_screenshot(hwnd, "publish-unverified")
        return False, "点击完成但校验没通过，可能没发出去"

    return True, "已发布"
```

**校验比点击重要**：点空了不发，用户看不到；发错了是社交事故。

## 五、屏幕适配：DPI 与分辨率

### 5.1 必须设置 DPI 感知

不设的话，150% 缩放系统会把坐标虚拟化，点谁谁偏。

```python
import ctypes

def set_dpi_aware():
    """进程级 DPI 感知。必须在任何窗口/坐标操作之前调用。"""
    try:
        # PER_MONITOR_AWARE_V2 = -4
        ctypes.windll.user32.SetProcessDpiAwarenessContext(ctypes.c_void_p(-4))
    except AttributeError:
        try:
            ctypes.windll.shcore.SetProcessDpiAwareness(2)   # PER_MONITOR
        except Exception:
            ctypes.windll.user32.SetProcessDPIAware()        # 老系统兜底
```

**项目里已经有了**：`bridge/bg_sender.py` 的 `_dpi_awareness()` 和
`click_screen()` 已经处理了物理/逻辑像素换算、客户区坐标转换。
朋友圈功能复用它，不要另写一套。

### 5.2 坐标统一用「客户区相对坐标」

```python
# 对：先拿客户区原点，再加偏移
left, top, w, h = client_rect(hwnd)
click_screen(left + dx, top + dy)

# 错：写死屏幕绝对坐标
click_screen(2524, 73)          # 换分辨率就废
```

### 5.3 多显示器

`Click 的屏幕坐标` 在多显示器下是虚拟桌面坐标（副屏可能是负数）。
`client_rect` 返回的已经是屏幕坐标，直接用即可；
但模板匹配截图时要用窗口自己的 `GetWindowRect`，不要用整屏截图。

## 六、风控与频率

库作者在 issue #36 的原话：

> 「封号应该不至于，但风控肯定是有的，只能说增加延迟能降低风控频率，但避免不了」

实践建议：

| 动作 | 建议间隔 | 说明 |
| --- | --- | --- |
| 读 | 无限制 | 不产生行为 |
| 赞 | ≥ 30 秒/次，每小时 ≤ 10 次 | 短时间连赞是典型风控特征 |
| 评论 | ≥ 60 秒/次，内容不要模板化 | 重复话术容易被识别 |
| 发布 | 每天 ≤ 3 条 | 内容风控 + 频率风控双重 |

另外：

- 不要在深夜批量操作（00:00-06:00 的行为更像脚本）
- 新号/小号风控阈值比老号低，别拿小号试
- 互动失败时**不要立刻重试**，等几分钟

## 七、已知坑

1. **多开一个「搜一搜」窗口会把朋友圈挤窄**，所有基于窗口宽度的坐标全废 → 操作前先关掉它。
2. **按 Esc 容易把微信主窗关成扫码登录页** → 不要用 Esc 收尾，用鼠标点关闭按钮。
3. **`GetMoments()` 会打开朋友圈窗口**（抢前台）；纯读请用 `MomentDB.get_moments()`。
4. **评论的「发送」按钮无 UIA 控件**，依赖模板匹配，模板缺失时会停在「已输入未发送」。
5. **`WeChatDB()` 需要管理员权限**：桥接进程如果不是管理员，读库会拿到 0 密钥。
6. **朋友圈内容是 XML**，正文里的 emoji/换行是转义过的，直接 str() 会看到实体编码，用 `parse_feed` 解析后的 `text` 才干净。

## 八、给后续实现的建议顺序

1. **先只做读**：`MomentDB.get_moments()`，接到聊天的话题/记忆里。零界面操作，可以先跑起来验证稳定性。
2. **再做赞**：单条、手动触发、带频率限制。
3. **评论放最后**：等模板匹配那段补齐，或者接受「输入完不自动发送」的半自动模式。
4. **发布不要自动化**：需要时人工点，或者只做「打开朋友圈界面并填好文字」的半自动辅助。
