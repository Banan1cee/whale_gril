# 提醒模块追加复核

基于 main 的 `04082b3`，逐项复核用户提供的《另外发现的问题》报告。

| 报告项目 | 当前代码复核与处理 |
| --- | --- |
| 重启后 sending 被复活 | 既有修复已在转换状态前检查原始 dueAt + 5 分钟；增加已领取任务重启后的落盘回归测试，确认超过原始窗口就 expired、不补发。 |
| 取消与回执冲突 | 既有回执状态检查阻止 cancelled → done；进一步拒绝取消 sending，避免微信已经开始发送却向用户宣称取消成功。聊天取消命令按实际取消数量回复，并说明正在发送的条数。 |
| 回执不幂等 | 既有状态检查阻止重复失败回执增加 attempts，重复成功回执维持原状态；追加完整失败、重复失败、重试成功、重复成功流程测试。 |
| 同批超过 10 条延迟 | 确认仍存在。nextDueAt 现在返回已到期队列的立即唤醒时间，桥接按 0.2 秒下限继续领下一批；也返回领取超时的唤醒时间。仍保留每批 10 条上限，避免一次占用大量发送任务。 |
| 提醒文件没有备份 | 确认仍存在。每次成功落盘后原子更新最新 .bak；主文件解析或结构校验失败时从备份恢复。两份均损坏时拒绝写入、保留原件，并记录读取错误。备份失败单独记录警告，不把已成功的主文件提交误报为失败。 |

另外发现并修复：`engine.main()` 调用了不存在的 `start_reminder_watch()`。现补齐调度器导入、HTTP 领取/回执、会话目标及普通/群 @ 发送适配、后台线程启动和退出时持有的 runner。接口状态错误或业务失败会拒绝继续发送，目标缺少 wxid 时拒绝发送。测试覆盖真实适配层与 engine 启动接线，避免只测独立调度器而漏掉主入口。

这些修改未调整 Memory V2 存储、压缩或 Token 预算逻辑。没有通过实际微信发送消息进行验收，微信版本兼容性与 UI 发送效果仍需要真实账号环境验证。这里的自动测试覆盖状态、文件恢复、调度等待和接口适配，不代表所有真实微信场景已经消除故障。
