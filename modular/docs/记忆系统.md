# 记忆系统

一句话：**记得住、会挑、会忘、人能管**。四件事分别对应四个模块。

```
对方说话
   │
   ├─ 检索（recall.js）        按这句话挑 3~5 条最相关的旧事
   └─ 摘要（digest.js 写的）    你们最近聊了什么
   │
   ▼
提示词里注入 → 生成回复
   │
   ▼ 回复写完之后（异步）
整理（digest.js）  每 12 条新消息：压成摘要 + 抽 0~3 条事实
   │
   ▼
存（store.js）→ 超上限按分数淘汰 → 淘汰/老化的沉到归档
   │
   ▼
忘（forget.js）  启动时 + 每次整理后扫一遍
```

## 存什么

| 存储 | 文件 | 说明 |
| --- | --- | --- |
| 主存 | `data/memory.json` | 会话、消息、每个人的人物档案、事实笔记、会话摘要。**唯一权威** |
| 归档 | `data/memory-archive.json` | 被忘掉的记忆，不再参与对话，可恢复、可彻底删除，上限 3000 条 |
| 备份 | `data/backups/` | 启动快照，手动/自动 |

一条记忆长这样：

```json
{ "text": "小海明天要去体检", "kind": "recent", "createdAt": 1730000000000,
  "lastMentionedAt": 0, "mentions": 0, "importance": 2 }
```

`kind` 五种：`fact`（普通事实）、`preference`（喜好）、`promise`（承诺/待办）、
`recent`（近况）、`taboo`（雷区）。承诺和雷区**永远不会被自动忘掉**。

## 怎么挑（recall.js）

```
第一层（便宜、每次必跑）：字面 2-gram 打分，用来排序和兜底
分数 = 字面重合(每个 2 分) + 重要度加成 + 类别权重
      + 越久没聊越值得翻(最多 +2) − 刚说过(−3 / −1)

第二层（语义判断，候选 ≥ 3 条才跑）：
把**最多 10 条候选**和对方这句话一起丢给模型，让它只挑真正相关的（宁缺勿滥），返回下标。
失败/没配 Key/演示模式 → 退回第一层的顺序，不会因此不回消息。

> 为什么这一层要看到「全量」而不只是字面 top：记忆里写「明天要去体检」、对方问
> 「医院那边几点集合」，字面一条都不重合，这条根本进不了字面候选。所以语义层
> 直接拿较大的候选集，让模型自己挑。
```

- 半小时内刚提过的那条，这一轮直接跳过，避免复读。
- **判断相关性完全交给模型**（`semantic.js`）。没有同义词表，也不需要人维护——
  词表补不完也补不准（「体检」对「医院」行，那「复查」「化验」呢？）。
- 被挑中的记忆会记一次 `lastMentionedAt`，下次别急着再念。

## 怎么忘（forget.js）

分数 = 重要度 × 0.5^(年龄/30天) × 类别权重 + 最近被想起的加成（半衰期 30 天）。

| 环节 | 触发 | 动作 |
| --- | --- | --- |
| 淘汰 | 某个人的记忆超过上限（默认 6 条） | 扔**分数最低**的，不是最老的；承诺/雷区最后才动 |
| 归档 | 45 天没被想起 + 分数 ≤ 0.35 + 非承诺/雷区 | 移到归档文件，不再进提示词 |
| 真删 | 归档超过 3000 条 | 扔掉最老的，磁盘上消失 |
| 消息裁剪 | 会话超过 `maxMessages` | **只删已经被摘要覆盖的**；没整理的留着（最多 2 倍上限） |

执行时机：启动时一次 + 每次整理之后。

## 整理（digest.js）

每攒够 `memory.digestEvery`（默认 12）条新消息，用一次模型调用同时拿到：

- `summary`：80~150 字，第三人称，写「最近在聊什么、关系状态、有没有未完成的事」
- `facts`：0~3 条关于对方的事实，带类别和重要度

失败（模型乱答、网络挂）就整批跳过，不影响回复。总开关 `memory.digest`（默认开）。

## 人能管

启动器 →「记忆」页：会话列表、每个人记得什么、立即备份/从快照恢复/导出。

**归档没有界面入口**（按需求）：忘掉的记忆写在 `data/memory-archive.json` 里，
当成审计日志看，超过 3000 条自动删最老的。要捞回来就手动改这个文件。

## 可调参数

| 配置 | 默认 | 含义 |
| --- | --- | --- |
| `memory.maxNotesPerUser` | 6 | 每人最多留几条记忆 |
| `memory.maxMessages` | 400 | 每个会话留多少条消息（未摘要的留到 2 倍） |
| `memory.digestEvery` | 12 | 攒多少条消息整理一次 |
| `memory.digest` | 开 | 自动整理总开关 |
| `memory.semantic` | 开 | 语义检索（让模型挑记忆） |
| `memory.semanticMinCandidates` | 3 | 候选达到几条才值得多问一次模型 |
| `forget.js` 里 `minAgeDays` / `maxScore` | 45 天 / 0.35 | 归档门槛 |
| `recall.js` 里 `pickNotes` 的 `limit` | 5 | 每次最多注入几条记忆 |

## 动作账本（她做过什么）

模型只会吐文字，所有副作用都是后端在它出完字之后干的：发表情包、把文字交给桥接、
读对方发的链接、联网查资料。这些结果以前只写日志，模型下一轮完全看不见，
于是「发了张图」它不知道、「刚才查的天气」它想不起来，被问到只能编或者装傻。

`src/core/events.js` + `store.appendEvent()` 补这一层：

| 类型 | 什么时候写 | detail 例 |
| --- | --- | --- |
| `sticker` | 挑中一张（queued）→ 桥接回执到了改写（confirmed / unconfirmed / failed） | `炸毛/wave.gif` |
| `send` | 只在**没到微信**或发送失败时写（成功的本来就在聊天记录里） | `1 条：哈哈哈` |
| `link` | 对方发链接、读完以后 | `https://… → 标题` |
| `web` | 联网/天气/热榜查完 | 对方原话前 60 字 |

- 存在会话的 `events` 字段里，**不进 messages**：不参与复读检测、不算回复、不影响摘要。
- 每个会话留 60 条，每轮只回读最近 12 条，拼成提示词里的【最近做过的事】。
- 一次发送只占一行：回执到了用 `store.updateEvent()` 原地改写排队那条。
- 状态措辞必须诚实：`unconfirmed` 写「桥接没回执，不确定是否发出」，不许写成已发送。

## 怎么验证

```bat
node --test --test-isolation=none "tests/*.test.js"
```

其中 `tests/memory-eval.test.js` 是**评估集**：30 轮脚本对话，量命中率（目标 ≥80%）、
复读率、遗忘是否讲道理、名额不够时谁先走。它曾经抓到过真问题（承诺的固定加权
压过了话题命中），调完参数现在是 20/20。

## 已知限制

1. **不是真的向量检索**：是把候选丢给模型判断（每次一次小调用、有 10 分钟缓存）。
   真要向量库得接 embedding 接口 + 存向量，当前记忆规模（每人几条到几十条）用不上。
2. 语义检索依赖模型可用；没 Key / 演示模式下只剩字面排序，「医院 ↔ 体检」会漏。
2. **整理要调模型**，关掉 `memory.digest` 就只回到「手动记住才写」。
3. **没有写失败队列**（outbox）：整理失败是跳过，不是排队重试。
4. 群聊里事实按「说话的人」归，不是按「关于谁」归。
